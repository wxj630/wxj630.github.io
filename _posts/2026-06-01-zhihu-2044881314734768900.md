<blockquote data-pid="W4Ydj5na">当前的大语言模型已经拥有非常丰富的知识和技能，但很多能力仍然需要被进一步验证。其中最重要的一类能力，是能否从经验和教训中反思，并持续改进自己的 Skills。我们把这种能力称为后天学习 <b>acquired learning</b>。</blockquote><figure data-size="normal"><img src="/assets/blog/images/23425017b1d8aeb3c914.png" data-size="normal" data-rawwidth="1672" data-rawheight="941" class="origin_image zh-lightbox-thumb" width="1672" data-original="/assets/blog/images/23425017b1d8aeb3c914.png"><figcaption>从三门问题到贝叶斯skill学习</figcaption></figure><p data-pid="5pn63QMG">Acquired learning refers to knowledge or skills gained through experience, education, or training.</p><p data-pid="n0viEHqF">在大语言模型系统里，这句话有一个很重要的工程含义：后天学习不一定要更新模型参数。预训练、后训练、强化学习、微调改变的是模型参数 <code>theta</code>；而 Skill、SOP、记忆、检索证据、失败案例、验证器反馈改变的是推理环境 <code>C</code>。</p><p data-pid="AZPtjnXg">所以我们可以把 LLM Agent 的学习分成两条路：</p><div class="highlight"><pre><code class="language-text"><span></span>参数训练学习:      theta -&gt; theta'
非参数后天学习:    C_t -&gt; C_{t+1}
</code></pre></div><p data-pid="WJiEmW73">Bayesian-Agent 做的是第二条路：不改 base model 的权重，而是从 verified trajectories 中学习 Skill 的可靠性、适用场景、失败模式和成本，让下一次推理拿到更好的条件。<b>也就是经验和教训（成功的轨迹我们称之为经验，失败的轨迹我们称之为教训）</b>。 也可以把它理解成一种归纳学习（inductive reasoning）：先用演绎法搭建模型结构，再用归纳法，也就是贝叶斯更新，从数据中学习参数或假设。</p><p data-pid="Sc59_38K">系列文章更新中：</p><blockquote data-pid="c4HdmRCZ">
<a href="https://zhuanlan.zhihu.com/p/2036275199008565089" class="internal" target="_blank">Bayesian Agent （一）：让 Harness 与 Skills 的 Self-Evolving过程不再黑盒、没有方向，走向贝叶斯信念</a> <br><a href="https://zhuanlan.zhihu.com/p/2036315473344714645" class="internal" target="_blank">Bayesian-Agent (二)：不仅是又一个 agent framework，而是可跨 harness 的 Bayesian Evolution Layer</a> </blockquote><h2>一、从三门问题开始：贝叶斯更新到底在更新什么</h2><p data-pid="M6FLbCv1">贝叶斯公式本身非常简单：</p><div class="highlight"><pre><code class="language-text"><span></span>P(H | E) = P(E | H) P(H) / P(E)
</code></pre></div><p data-pid="xzCIi4yJ">其中：</p><table data-draft-node="block" data-draft-type="table" data-size="normal" data-row-style="normal"><tbody>
<tr>
<th>符号</th>
<th>名称</th>
<th>含义</th>
</tr>
<tr>
<td>H</td>
<td>Hypothesis / 假设</td>
<td>我们想判断真假的事情</td>
</tr>
<tr>
<td>E</td>
<td>Evidence / 证据</td>
<td>我们观察到的新信息</td>
</tr>
<tr>
<td>P(H)</td>
<td>Prior / 先验</td>
<td>看到证据之前，对假设的相信程度</td>
</tr>
<tr>
<td>P(E | H)</td>
<td>Likelihood / 似然</td>
<td>如果假设为真，观察到该证据的概率</td>
</tr>
<tr>
<td>P(H | E)</td>
<td>Posterior / 后验</td>
<td>看到证据之后，对假设的更新信念</td>
</tr>
<tr>
<td>P(E)</td>
<td>Evidence / 边际概率</td>
<td>证据整体出现的概率，也起归一化作用</td>
</tr>
</tbody></table><p data-pid="Q_HYUaIm">也可以写成更常用的比例形式：</p><div class="highlight"><pre><code class="language-text"><span></span>posterior ∝ likelihood * prior
</code></pre></div><p data-pid="vipqtbsp">也就是：</p><div class="highlight"><pre><code class="language-text"><span></span>新的信念 ∝ 证据在该假设下出现的概率 * 原来的信念
</code></pre></div><p data-pid="aqy8RQYZ">三门问题是最经典的贝叶斯直觉测试：</p><ol>
<li data-pid="iwFkAOny">有三扇门，一扇门后面是车，另外两扇门后面是羊。</li>
<li data-pid="tbfAAWQb">你先选一扇门，比如 A。</li>
<li data-pid="1dyOxGci">主持人知道答案，并打开另一扇有羊的门，比如 B。</li>
<li data-pid="cv5lmYVZ">你现在可以坚持 A，也可以换到 C。</li>
</ol><p data-pid="8v1ZUFfo">很多人的直觉会说：现在只剩两扇门，所以 A 和 C 各有 <code>1/2</code>。但正确答案是：应该换门，换到 C 的胜率是 <code>2/3</code>。</p><p data-pid="lkbKaOTl">关键点是：主持人的行为不是随机噪声，而是有条件的信息。主持人打开 B，不只是“少了一扇门”，而是在告诉你：“在知道车在哪的前提下，我选择打开了 B 这扇羊门。”</p><p data-pid="kGrKrKsg">设：</p><div class="highlight"><pre><code class="language-text"><span></span>H_A: 车在 A 后面
H_C: 车在 C 后面
O_B: 主持人打开 B
</code></pre></div><p data-pid="DJcVJV1C">一开始：</p><div class="highlight"><pre><code class="language-text"><span></span>P(H_A) = 1/3
P(H_B) = 1/3
P(H_C) = 1/3
</code></pre></div><p data-pid="EQrLfk-k">当你选 A 后，主持人打开 B。因为主持人不会打开你选的门，也不会打开车门，所以：</p><div class="highlight"><pre><code class="language-text"><span></span>P(O_B | H_A) = 1/2
P(O_B | H_C) = 1
P(O_B | H_B) = 0
</code></pre></div><p data-pid="pXN-4WGq">用贝叶斯公式：</p><div class="highlight"><pre><code class="language-text"><span></span>P(H_i | O_B) = P(O_B | H_i) P(H_i) / sum_j P(O_B | H_j) P(H_j)
</code></pre></div><p data-pid="S01vuGb-">这里的对应关系是：</p><table data-draft-node="block" data-draft-type="table" data-size="normal" data-row-style="normal"><tbody>
<tr>
<th>项</th>
<th>三门问题里的含义</th>
</tr>
<tr>
<td>Prior P(H_i)</td>
<td>主持人开门前，车在每扇门后的概率</td>
</tr>
<tr>
<td>Likelihood P(O_B | H_i)</td>
<td>如果车在某扇门后，主持人打开 B 的概率</td>
</tr>
<tr>
<td>Posterior P(H_i | O_B)</td>
<td>主持人打开 B 后，车在某扇门后的概率</td>
</tr>
<tr>
<td>Evidence P(O_B)</td>
<td>主持人打开 B 这个事件整体发生的概率</td>
</tr>
</tbody></table><p data-pid="o73_pN9p">于是：</p><div class="highlight"><pre><code class="language-text"><span></span>P(H_A | O_B)
= (1/2 * 1/3) / (1/2 * 1/3 + 1 * 1/3 + 0 * 1/3)
= 1/3

P(H_C | O_B)
= (1 * 1/3) / (1/2 * 1/3 + 1 * 1/3 + 0 * 1/3)
= 2/3
flowchart LR
    A["Prior: 每扇门 1/3"] --&gt; B["Observation: 主持人打开 B"]
    B --&gt; C["Likelihood: P(O_B | H_i)"]
    C --&gt; D["Posterior: A=1/3, C=2/3"]
    D --&gt; E["Decision: 换门"]
</code></pre></div><p data-pid="wxErXzAE">严格说，三门问题讲的是贝叶斯更新。Agent 的运行轨迹更复杂：一次任务会同时产生 context、failure mode、token cost、tool turns、latency、metadata 等多个证据特征。Bayesian-Agent 需要的是一个能把这些特征转成 posterior belief 的 <b>Bayesian Evidence Model</b>。</p><h2>二、Bayesian Evidence Model：当证据不止一个时怎么办</h2><p data-pid="bsu7uNkY">先看一个最小化的 categorical evidence model。给定一组特征 <code>x</code>，判断它属于哪个标签 <code>y</code>：</p><div class="highlight"><pre><code class="language-text"><span></span>x = {x_1, x_2, ..., x_m}
y in {class_1, class_2, ...}
</code></pre></div><p data-pid="hioJIT9V">直接用贝叶斯公式：</p><div class="highlight"><pre><code class="language-text"><span></span>P(y | x) = P(x | y) P(y) / P(x)
</code></pre></div><p data-pid="3MGkPYmH">问题是 <code>x</code> 不是一个单独事件，而是一组特征：</p><div class="highlight"><pre><code class="language-text"><span></span>P(y | x_1, x_2, ..., x_m)
= P(x_1, x_2, ..., x_m | y) P(y) / P(x_1, x_2, ..., x_m)
</code></pre></div><p data-pid="guRM1esu">如果特征很多，直接估计联合概率 <code>P(x_1, x_2, ..., x_m | y)</code> 会非常困难。目前采用一个轻量的 factorized categorical likelihood：在给定标签 <code>y</code> 后，各个特征近似条件独立（即朴素贝叶斯的方案）：</p><div class="highlight"><pre><code class="language-text"><span></span>P(x_1, x_2, ..., x_m | y)
≈ Π_j P(x_j | y)
</code></pre></div><p data-pid="fHSytU8w">这里的 <code>Π</code> 是大写希腊字母 Pi，在数学里表示 <b>product / 连乘</b>。<code>Π_j P(x_j | y)</code> 的意思是：</p><div class="highlight"><pre><code class="language-text"><span></span>P(x_1 | y) * P(x_2 | y) * ... * P(x_m | y)
</code></pre></div><p data-pid="GSenhYFG">于是：</p><div class="highlight"><pre><code class="language-text"><span></span>P(y | x)
∝ P(y) Π_j P(x_j | y)
</code></pre></div><p data-pid="1If4lmgK">归一化以后得到：</p><div class="highlight"><pre><code class="language-text"><span></span>P(y = c | x)
= P(c) Π_j P(x_j | c) / sum_{c'} P(c') Π_j P(x_j | c')
</code></pre></div><p data-pid="Ln56Puxr">这里的对应关系是：</p><table data-draft-node="block" data-draft-type="table" data-size="normal" data-row-style="normal"><tbody>
<tr>
<th>项</th>
<th>Evidence model 里的含义</th>
</tr>
<tr>
<td>Prior P(c)</td>
<td>某个类别本来出现的概率</td>
</tr>
<tr>
<td>Likelihood Π_j P(x_j | c)</td>
<td>如果类别是 c，这些特征一起出现的概率近似</td>
</tr>
<tr>
<td>Posterior P(c | x)</td>
<td>看到这些特征后，样本属于类别 c 的概率</td>
</tr>
<tr>
<td>Evidence P(x)</td>
<td>这些特征整体出现的概率，通常用归一化分母处理</td>
</tr>
</tbody></table><h3>例子：一封邮件是不是垃圾邮件</h3><p data-pid="QTJ_ik4o">假设我们要判断一封邮件是不是垃圾邮件：</p><div class="highlight"><pre><code class="language-text"><span></span>y in {spam, normal}
</code></pre></div><p data-pid="vlncBtFs">观察到三个特征：</p><div class="highlight"><pre><code class="language-text"><span></span>x_1 = contains_discount      # 邮件里出现“折扣”
x_2 = contains_link          # 邮件里有链接
x_3 = sender_unknown         # 发件人陌生
</code></pre></div><p data-pid="oQEmWQ0b">从历史邮件里统计到：</p><div class="highlight"><pre><code class="language-text"><span></span>P(spam) = 0.30
P(normal) = 0.70

P(contains_discount | spam) = 0.80
P(contains_link | spam) = 0.70
P(sender_unknown | spam) = 0.60

P(contains_discount | normal) = 0.10
P(contains_link | normal) = 0.20
P(sender_unknown | normal) = 0.05
</code></pre></div><p data-pid="zPbSjIGH">那么这封邮件是垃圾邮件的未归一化分数是：</p><div class="highlight"><pre><code class="language-text"><span></span>score(spam)
= P(spam)
  * P(contains_discount | spam)
  * P(contains_link | spam)
  * P(sender_unknown | spam)

= 0.30 * 0.80 * 0.70 * 0.60
= 0.1008
</code></pre></div><p data-pid="cN1ssW3n">普通邮件的未归一化分数是：</p><div class="highlight"><pre><code class="language-text"><span></span>score(normal)
= P(normal)
  * P(contains_discount | normal)
  * P(contains_link | normal)
  * P(sender_unknown | normal)

= 0.70 * 0.10 * 0.20 * 0.05
= 0.0007
</code></pre></div><p data-pid="cC2hHbmt">归一化：</p><div class="highlight"><pre><code class="language-text"><span></span>P(spam | x)
= score(spam) / (score(spam) + score(normal))
= 0.1008 / (0.1008 + 0.0007)
≈ 0.993
</code></pre></div><p data-pid="JHmbMY11">所以模型会判断这封邮件大概率是垃圾邮件。</p><p data-pid="-TCUFdhH">这个例子里：</p><table data-draft-node="block" data-draft-type="table" data-size="normal" data-row-style="normal"><tbody>
<tr>
<th>概念</th>
<th>对应内容</th>
</tr>
<tr>
<td>Prior</td>
<td>P(spam) 和 P(normal)，历史上垃圾邮件/普通邮件的比例</td>
</tr>
<tr>
<td>Likelihood</td>
<td>P(contains_discount | spam) 等特征在某类邮件下出现的概率</td>
</tr>
<tr>
<td>Posterior</td>
<td>P(spam | x)，看到这些特征后邮件是垃圾邮件的概率</td>
</tr>
<tr>
<td>Factorization assumption</td>
<td>给定 spam 或 normal 后，折扣、链接、陌生发件人近似独立</td>
</tr>
</tbody></table><p data-pid="ss420HFR">这就是 categorical evidence model 的直觉：它不需要理解“折扣”和“链接”的深层语义，只要不断从历史样本里统计“哪些特征经常和哪个标签一起出现”，就可以做出可解释的概率判断。在 Bayesian-Agent 里，它被定位为第一个可解释 evidence backend，而不是方法的上限。</p><h2>三、人的后天学习：一个技能是如何从经验里长出来的</h2><p data-pid="B8ubIy9v">假设一个人正在学习写 SQL 报表。他不是从零拥有“SQL 专家能力”的。最开始，他可能已经知道一些语法：</p><div class="highlight"><pre><code class="language-text"><span></span>SELECT, WHERE, GROUP BY, HAVING, ORDER BY
</code></pre></div><p data-pid="oem1khQg">这相当于他的先验知识。可是，真正做任务时，他会不断遇到经验和教训：</p><ul>
<li data-pid="ZAyJfzr8">有些任务需要先读表结构，否则会写错列名。</li>
<li data-pid="Fz1RJpJk">有些任务需要 <code>GROUP BY</code>，否则聚合结果错误。</li>
<li data-pid="yv7BEzL2">有些任务要求“只输出一条 SQL”，如果写解释文字就会失败。</li>
<li data-pid="SSjWNW4s">有些更新任务不能带自增主键列。</li>
<li data-pid="uQj9MEcZ">有些失败不是知识不会，而是没有验证输出。</li>
</ul><p data-pid="ZHg4s1WZ">每一次任务之后，如果有老师、测试用例或数据库执行结果给出反馈，那么这个人就会获得一条 evidence：</p><div class="highlight"><pre><code class="language-text"><span></span>e_i = (x_i, y_i)
</code></pre></div><p data-pid="xknRpFKO">其中：</p><div class="highlight"><pre><code class="language-text"><span></span>x_i = {
  task_type,
  schema_complexity,
  required_operator,
  failure_mode,
  verification_signal
}

y_i in {success, failure}
</code></pre></div><p data-pid="EJP37rib">如果我们把“先读 schema、再写 SQL、最后执行验证”看成一条 Skill hypothesis <code>h_sql_verify</code>，为了避免记号太长，可以把“在这条 Skill 作用域下的概率”写成 <code>P_h(...)</code>，其中：</p><div class="highlight"><pre><code class="language-text"><span></span>h = h_sql_verify
P_h(y | x) 等价于 P(y | x, h_sql_verify)
</code></pre></div><p data-pid="rUkFU7HH">这和前面垃圾邮件例子里的 <code>P(spam | x)</code> 是同一种结构。垃圾邮件例子里，分类器或历史邮件统计这个“模型作用域”是隐含的；到了 Skill 学习里，我们把它显式写出来，因为不同 Skill 会有不同的历史证据和成功率。</p><p data-pid="7FJKHrJt">于是后天学习可以写成：</p><div class="highlight"><pre><code class="language-text"><span></span>P_h(success | x)
∝ P_h(success) Π_j P_h(x_j | success)
</code></pre></div><p data-pid="a4dy7Bjc">更完整地写，就是：</p><div class="highlight"><pre><code class="language-text"><span></span>P_h(y | x)
= P_h(y) Π_j P_h(x_j | y)
  / sum_{y'} P_h(y') Π_j P_h(x_j | y')
</code></pre></div><p data-pid="gTi2gZ-P">这里的 prior、likelihood、posterior 可以一一对应：</p><table data-draft-node="block" data-draft-type="table" data-size="normal" data-row-style="normal"><tbody>
<tr>
<th>贝叶斯概念</th>
<th>后天学习里的含义</th>
</tr>
<tr>
<td>Prior P_h(y)</td>
<td>在这条 Skill 作用域下，看到当前任务特征前的历史成功/失败倾向</td>
</tr>
<tr>
<td>Likelihood Π_j P_h(x_j | y)</td>
<td>如果这次会成功或失败，那么当前这些任务特征出现的概率</td>
</tr>
<tr>
<td>Posterior P_h(y | x)</td>
<td>看到当前任务特征后，这条 Skill 成功或失败的更新概率</td>
</tr>
<tr>
<td>Evidence P_h(x)</td>
<td>在这条 Skill 作用域下，当前任务特征整体出现的概率，用分母归一化</td>
</tr>
</tbody></table><p data-pid="H8OBDVvJ">举一个很小的数值例子。学习者过去用 <code>h_sql_verify</code> 做过 10 个 SQL 任务，其中 6 次成功、4 次失败。用 <code>alpha = 1</code> 做平滑：</p><div class="highlight"><pre><code class="language-text"><span></span>P_h(success) = (6 + 1) / (10 + 2) = 7/12
P_h(failure) = (4 + 1) / (10 + 2) = 5/12
</code></pre></div><p data-pid="MI4ITk1L">这就是 prior。现在来了一个新任务，它的特征是：</p><div class="highlight"><pre><code class="language-text"><span></span>x_1 = task_type=aggregation
x_2 = required_operator=GROUP_BY
x_3 = verification_signal=executed_ok
</code></pre></div><p data-pid="CO0_scXo">从过去经验里统计到：</p><div class="highlight"><pre><code class="language-text"><span></span>P_h(task_type=aggregation | success) = 4/6
P_h(required_operator=GROUP_BY | success) = 4/6
P_h(verification_signal=executed_ok | success) = 5/6

P_h(task_type=aggregation | failure) = 3/4
P_h(required_operator=GROUP_BY | failure) = 1/4
P_h(verification_signal=executed_ok | failure) = 1/4
</code></pre></div><p data-pid="bcR1Q1QI">这些就是 likelihood。于是：</p><div class="highlight"><pre><code class="language-text"><span></span>score(success)
= 7/12 * 4/6 * 4/6 * 5/6
≈ 0.216

score(failure)
= 5/12 * 3/4 * 1/4 * 1/4
≈ 0.0195

P_h(success | x)
= 0.216 / (0.216 + 0.0195)
≈ 0.917
</code></pre></div><p data-pid="dFRKGr_Z">这就是 posterior。人的直觉说法是：“这类任务我已经掌握了，只要按 checklist 执行验证，成功率很高。”贝叶斯说法是：“在这条 Skill 和这些 evidence features 下，posterior success probability 升高了。”</p><p data-pid="9VcDc2hG">如果一个学习者反复观察到：</p><div class="highlight"><pre><code class="language-text"><span></span>task_type = aggregation
required_operator = GROUP BY
verification_signal = executed_ok
</code></pre></div><p data-pid="bmbMTlhG">这些特征经常和成功一起出现，那么这条 Skill 的 posterior success 就会上升。相反，如果：</p><div class="highlight"><pre><code class="language-text"><span></span>failure_mode = missing_group_by
verification_signal = not_executed
</code></pre></div><p data-pid="g_jvfTpH">经常和失败一起出现，那么学习者会形成一个新的经验：</p><div class="highlight"><pre><code class="language-text"><span></span>遇到聚合任务时，不要只写 SELECT；必须检查 GROUP BY/HAVING，并执行验证。
</code></pre></div><p data-pid="lvaNKmBx">这就是后天学习。人的大脑参数当然也会变化，但从工程视角看，很多可复用的能力沉淀在外部结构里：</p><ul>
<li data-pid="iXSrgKG9">笔记</li>
<li data-pid="jUUuY5RX">checklist</li>
<li data-pid="-QP-uvcB">SOP</li>
<li data-pid="ezTEDPjm">失败案例本</li>
<li data-pid="lNxMVsGL">测试习惯</li>
<li data-pid="dX8lQ4UV">反思模板</li>
<li data-pid="NoMZFW5e">面向场景的操作策略</li>
</ul><p data-pid="PlbzJMIr">在 LLM Agent 里，这些外部结构就是 Skills、SOPs、memory、tool traces 和 verifier feedback。它们不改变 <code>theta</code>，但改变下一次推理的条件：</p><div class="highlight"><pre><code class="language-text"><span></span>P(X | theta) -&gt; P(X | theta, C)
</code></pre></div><p data-pid="iiLyRuXt">更进一步，后天学习就是让 <code>C</code> 随经验更新：</p><div class="highlight"><pre><code class="language-text"><span></span>C_{t+1} = Update(C_t, evidence_t)
flowchart TD
    A["Task"] --&gt; B["Attempt with current Skill"]
    B --&gt; C["Verifier / Teacher Feedback"]
    C --&gt; D["Evidence: context, outcome, failure mode"]
    D --&gt; E["Belief update"]
    E --&gt; F["Skill patch / split / compress / retire"]
    F --&gt; G["Better Skill context for next task"]
    G --&gt; A
</code></pre></div><p data-pid="cpQ6C30q">这和参数训练不同。参数训练是在改变模型内部的 <code>theta</code>。后天学习是在改变模型外部的 <code>C</code>，让同一个模型在下一次推理时拥有更好的证据、更好的步骤、更好的失败规避策略。</p><h2>四、Bayesian-Agent：把 Skill 当成可验证的假设</h2><p data-pid="Aa4QKn2k">Bayesian-Agent 的核心观点是：</p><blockquote data-pid="deJVl_tR"> Skill/SOP 不是一段神圣的提示词，而是一个关于“如何让 Agent 成功”的 hypothesis。</blockquote><p data-pid="qgWTSTvp">记：</p><div class="highlight"><pre><code class="language-text"><span></span>h_k = 第 k 条 Skill/SOP hypothesis
x = 当前任务和运行证据特征
y in {success, failure}
</code></pre></div><p data-pid="KGd6zKFh">大语言模型本身拥有丰富知识：</p><div class="highlight"><pre><code class="language-text"><span></span>P(X | theta)
</code></pre></div><p data-pid="zwOcGX45">Agent 系统则会把模型放进某个推理环境里：</p><div class="highlight"><pre><code class="language-text"><span></span>P(X | theta, C)
</code></pre></div><p data-pid="dApyxAxL">这里的 <code>C</code> 包括 prompt、tools、memory、RAG、Skill、SOP、历史轨迹和 verifier feedback。Bayesian-Agent 不直接更新 <code>theta</code>，而是更新 <code>C</code> 中的 Skill belief：</p><div class="highlight"><pre><code class="language-text"><span></span>P_{h_k}(success | x)
</code></pre></div><p data-pid="SDLKWKH_">这里的 <code>P_{h_k}(...)</code> 表示“在第 <code>k</code> 条 Skill/SOP 的证据作用域下计算概率”。它等价于 <code>P(success | x, h_k)</code>，只是把 <code>h_k</code> 放到下标里，避免读者把 <code>h_k</code> 误解成和 <code>x</code> 同级的普通特征。</p><p data-pid="C7xkcEnM">每次 Agent 跑完一个任务，Bayesian-Agent 会收集一条 verified trajectory：</p><div class="highlight"><pre><code class="language-text"><span></span>e_i = {
  task_id,
  skill_id,
  context,
  outcome,
  failure_mode,
  input_tokens,
  output_tokens,
  total_tokens,
  turns,
  elapsed_seconds,
  metadata
}
</code></pre></div><p data-pid="2sMgFy-X">这些 evidence 进入 Skill registry，形成每条 Skill 的 posterior belief。</p><p data-pid="Uhb16Vy0">在 Bayesian-Agent 里，对应关系是：</p><table data-draft-node="block" data-draft-type="table" data-size="normal" data-row-style="normal"><tbody>
<tr>
<th>贝叶斯概念</th>
<th>Bayesian-Agent 里的含义</th>
</tr>
<tr>

<td>第 k 条 Skill/SOP</td>
</tr>
<tr>
<td>Evidence e_i</td>
<td>一次经过验证的 agent trajectory</td>

<tr>

</tbody></table><h2>五、Benchmark 例子：从零进化、失败改写与增量修复</h2><p data-pid="sXZJICcl">上面的公式还是抽象。下面看几组 benchmark 轨迹，分别展示三种情况：</p><div class="highlight"><pre><code class="language-text"><span></span>clean full mode:  从零开始跑，但一路成功，只展示 reliability posterior 上升

</code></pre></div><p data-pid="rtTOMPUa">前两题成功：</p><div class="highlight"><pre><code class="language-text"><span></span>sop_01: success
sop_02: success

P_h_base(success)
= (2 + 1) / (2 + 0 + 2)
= 0.750
</code></pre></div><p data-pid="KLsaDEg_">这时系统还不会改写 Skill，只会认为基础 SOP skill 在当前 harness 下初步可靠。</p><p data-pid="8rEbC9zp">接下来出现两个相似失败：</p><div class="highlight"><pre><code class="language-text"><span></span>sop_13: failure, failure_mode = left_expected_output_blank
sop_14: failure, failure_mode = left_expected_output_blank
</code></pre></div><p data-pid="ZBdxbkqK">也就是 Agent 算出了流程，却没有把目标 CSV 行的 <code>expected_output</code> 写成非空值。当前观测到的任务特征是：</p><div class="highlight"><pre><code class="language-text"><span></span>context = sop_bench
metadata.output_contract = csv_expected_output
failure_mode = left_expected_output_blank
</code></pre></div><p data-pid="Li8njEnl">这里的 <code>failure_mode = left_expected_output_blank</code> 表示“expected_output 留空”这个具体错误类型；它不是 <code>failure</code> 标签本身。</p><p data-pid="FifX69Ww">此时基础 Skill 的证据是：</p><div class="highlight"><pre><code class="language-text"><span></span>success = 2

</code></pre></div><p data-pid="RitfWaUX">再看关键 feature 的 likelihood。<code>failure_mode</code> 是这次失败中最关键的特征；真实实现还会把 <code>context</code>、token bucket、turn bucket、latency bucket 和 metadata 一起连乘进去。</p><p data-pid="aw4btlB8">在两条成功轨迹里，<code>failure_mode = left_expected_output_blank</code> 出现了 0 次；在两条失败轨迹里，它出现了 2 次。用 Laplace smoothing：</p><div class="highlight"><pre><code class="language-text"><span></span>P_h_base(failure_mode = left_expected_output_blank | success)

= 0.750
</code></pre></div><p data-pid="QPdJonLy">于是 Bayesian Evidence Model 的 posterior 如下：</p><div class="highlight"><pre><code class="language-text"><span></span>score_success
= P(success) * P(failure_mode = left_expected_output_blank | success)
= 0.500 * 0.250
= 0.125

score_failure
= P(failure) * P(failure_mode = left_expected_output_blank | failure)
= 0.500 * 0.750
= 0.375

P_h_base(
    failure
  | context = sop_bench,
    metadata.output_contract = csv_expected_output,
    failure_mode = left_expected_output_blank
)
= 0.375 / (0.125 + 0.375)
= 0.750

P_h_base(
    success
  | context = sop_bench,
    metadata.output_contract = csv_expected_output,
    failure_mode = left_expected_output_blank
)
= 0.250
</code></pre></div><p data-pid="s2zuA5M5">这一步很重要：失败不是让系统“更相信原来的 Skill”，而是让系统更相信：</p><div class="highlight"><pre><code class="language-text"><span></span>在 context = sop_bench, metadata.output_contract = csv_expected_output,
failure_mode = left_expected_output_blank 这个条件下，
h_base 很可能继续失败。
</code></pre></div><p data-pid="WAxUl241">因此 rewrite policy 不应该 <code>compress</code>，而应该 <code>patch</code> 或 <code>split</code>：</p><div class="highlight"><pre><code class="language-text"><span></span>rewrite = patch
reason = failures cluster around left_expected_output_blank
</code></pre></div><p data-pid="7D_Hy3OA">改写后的 Skill context 不是泛泛地说“仔细一点”，而是把失败模式变成可执行约束。当前实现会在下一轮 prompt 里注入类似这样的 patch section：</p><div class="highlight"><pre><code class="language-text"><span></span>### Bayesian Failure-Mode Patches: sop_bench

</code></pre></div><p data-pid="KaQb8Grd">然后用改写后的 Skill context 继续处理相似任务。后续成功会回写到同一条 benchmark Skill；失败历史不会被洗掉，posterior 会在保留 failure-mode 记忆的同时重新上升：</p><table data-draft-node="block" data-draft-type="table" data-size="normal" data-row-style="normal"><tbody>

  带 patch context 的 Skill 连续成功

  P_h_base(success) 从 0.500 -&gt; 0.571 -&gt; 0.625 -&gt; 0.667
</code></pre></div><p data-pid="aELR4IQZ">换句话说，Bayesian-Agent 里的“后验升高”有两种不同含义：</p><div class="highlight"><pre><code class="language-text"><span></span>正向经验:
  success evidence 让同一条 Skill 的 posterior_success 升高

失败改写:
  failure evidence 先让原 Skill 在某个条件下的 posterior_failure 升高，

-&gt; 只重跑失败任务
-&gt; 成功轨迹回写 registry
-&gt; 下一轮 Skill 更可靠
</code></pre></div><h2>六、从 Beta-Bernoulli 到 Bayesian Evidence Model</h2><p data-pid="t_d4jCjq">最简单的贝叶斯 Skill update 是 Beta-Bernoulli。对一条 Skill <code>h_k</code>，只看成功和失败次数：</p><div class="highlight"><pre><code class="language-text"><span></span>p_k ~ Beta(alpha_0, beta_0)
y_i ~ Bernoulli(p_k)
</code></pre></div><p data-pid="F5PmgkD9">观察到 <code>s_k</code> 次成功、<code>f_k</code> 次失败后：</p><div class="highlight"><pre><code class="language-text"><span></span>p_k | D_k ~ Beta(alpha_0 + s_k, beta_0 + f_k)
E[p_k | D_k] = (alpha_0 + s_k) / (alpha_0 + beta_0 + s_k + f_k)
</code></pre></div><p data-pid="Qq5BGdbR">这个模型很清晰，但它有一个问题：它只知道“这条 Skill 总体成功率是多少”，不知道“它在哪类 context 下成功，在哪类 failure mode 下失败”。</p><p data-pid="qA2mT_li">于是我们升级到 feature-conditioned Bayesian Evidence Model。</p><p data-pid="g1QhbFpV">Bayesian-Agent 当前默认把每条 Skill 的 evidence 特征离散化：</p><div class="highlight"><pre><code class="language-text"><span></span>x = {
  context,
  failure_mode,
  token_bucket,
  turn_bucket,
  latency_bucket,
  metadata.*
}
</code></pre></div><p data-pid="2Ut8J9s-">对每条 Skill <code>h_k</code>，维护：</p><div class="highlight"><pre><code class="language-text"><span></span>P_{h_k}(y) = (N_y + alpha) / (N + alpha * |Y|)

P_{h_k}(x_j = v | y)
= (N_{j,v,y} + alpha) / (N_{j,y} + alpha * |V_j|)
</code></pre></div><p data-pid="gVbkK6Cw">预测当前 context 下这条 Skill 的成功率：</p><div class="highlight"><pre><code class="language-text"><span></span>P_{h_k}(y = success | x)
∝ P_{h_k}(y = success) Π_j P_{h_k}(x_j | y = success)
</code></pre></div><p data-pid="amOAhz8K">完整归一化形式是：</p><div class="highlight"><pre><code class="language-text"><span></span>P_{h_k}(y = success | x)
= score(success) / (score(success) + score(failure))

score(y)
= P_{h_k}(y) Π_j P_{h_k}(x_j | y)
</code></pre></div><p data-pid="iMAbMvJy">其中：</p><ul>
<li data-pid="929U8BK0">
<code>N_y</code> 是这条 Skill 下某个标签的次数。</li>
<li data-pid="NWEN76hx">
<code>N_{j,v,y}</code> 是在标签 <code>y</code> 下，第 <code>j</code> 个特征取值为 <code>v</code> 的次数。</li>
<li data-pid="eR80-Wjg">
<code>|V_j|</code> 是第 <code>j</code> 个特征的取值空间大小。</li>
<li data-pid="F6KyRN0P">
<code>alpha = 1</code> 是 Laplace smoothing，用来避免未见过的特征导致概率为 0。</li>
</ul><p data-pid="gzWqxCAW">直觉上，这相当于让 Agent 形成这样的经验：</p><div class="highlight"><pre><code class="language-text"><span></span>这条 Skill 在 SOP-Bench 上通常成功。
这条 Skill 遇到 missing_group_by 这类 failure mode 时要 patch。
这条 Skill 在高 token bucket 下可能变慢。
这条 Skill 在 SQL mutation tasks 里必须先检查主键列。
</code></pre></div><p data-pid="8GZiRSnc">它不是凭感觉记忆，而是把每次 verified outcome 变成条件概率。</p><h2>七、Bayesian-Agent 的后天学习闭环</h2><p data-pid="Rr1aJqHS">Bayesian-Agent 的 acquired learning loop 可以写成：</p><div class="highlight"><pre><code class="language-text"><span></span>S_t = Skill registry at time t
e_t = verified trajectory evidence
S_{t+1} = BayesianUpdate(S_t, e_t)
C_{t+1} = RenderContext(S_{t+1}, task_context)
</code></pre></div><p data-pid="V6jBZS1V">下一次推理变成：</p><div class="highlight"><pre><code class="language-text"><span></span>P(X | theta, C_{t+1})
</code></pre></div><p data-pid="I_HuDQMW">也就是说，模型参数没变，但推理条件变了。Agent 不再只是“带着一长串记忆继续猜”，而是拿到 posterior-weighted Skill context：</p><div class="highlight"><pre><code class="language-text"><span></span>Use these Skills/SOPs as hypotheses, not as unquestioned instructions.
- skill_a: algorithm=categorical_bayes, posterior_success=0.95, context_success=0.92, rewrite=compress
- skill_b: algorithm=categorical_bayes, posterior_success=0.42, context_success=0.21, rewrite=patch
flowchart LR
    A["Base LLM: theta fixed"] --&gt; B["Agent Harness"]
    B --&gt; C["Task Execution"]
    C --&gt; D["Verifier"]
    D --&gt; E["Trajectory Evidence"]
    E --&gt; F["Bayesian Evidence Registry"]
    F --&gt; G["Posterior-weighted Skill Context"]
    G --&gt; B
</code></pre></div><p data-pid="gn7dh9Y9">这个过程有三个重要特征：</p><ol>
<li data-pid="scK1AQzk">
<b>从零学习</b>：没有历史 traces 时，Agent 也可以边跑任务边积累 evidence。</li>
<li data-pid="pjQf8q49">
<b>增量修复</b>：已有 Agent 跑失败的任务，可以只把失败轨迹交给 Bayesian-Agent，然后只重跑失败项。</li>
<li data-pid="z4WZ79xj">
<b>跨 harness 适配</b>：只要外部 Agent 能产出 trajectory evidence，并能接收 Skill context，就可以接入。</li>
</ol><h2>八、为什么这是 LLM Agent 的关键能力</h2><p data-pid="LJColJuW">当前的大语言模型知识和技能已经非常丰富。很多时候，模型不是“不知道”，而是：</p><ul>
<li data-pid="k_otfzw9">没有检查当前文件。</li>
<li data-pid="DwGUf9mT">没有验证工具输出。</li>
<li data-pid="KI4v30Lw">没有识别失败模式。</li>
<li data-pid="McWoUTzE">没有把上次失败转化成下一次的约束。</li>
<li data-pid="QGLWFmVY">没有区分这个 Skill 在哪个 context 下可靠。</li>

by updating external Skill/SOP beliefs from verified experience,
without changing the base model parameters.
</code></pre></div><p data-pid="Jrp9WyZI">也就是说：</p><div class="highlight"><pre><code class="language-text"><span></span>Agent 的后天学习，是指在不更新 base model 参数的情况下，
通过验证过的经验和教训，更新外部 Skill/SOP belief，
从而改善后续任务行为的非参数学习过程。
</code></pre></div><p data-pid="xv6xbsq-">这里的“非参数”不是说整个系统没有参数，而是说它不更新 LLM 的权重 <code>theta</code>。它更新的是外部推理环境：</p><div class="highlight"><pre><code class="language-text"><span></span>theta 固定
C 持续进化
Skill belief 持续被 evidence 校准
</code></pre></div><p data-pid="PgpkeoHU">这也是 Bayesian-Agent 想表达的核心范式：</p><div class="highlight"><pre><code class="language-text"><span></span>Pre-training gives the model knowledge.
Post-training aligns the model behavior.
Acquired learning lets the agent learn from its own verified experience.
</code></pre></div><p data-pid="NHHgYD7w">预训练给模型知识，后训练塑造模型行为，后天学习让 Agent 从自己的经验和教训里持续进化。</p><h2>十、为什么需要贝叶斯？？？</h2><p data-pid="f0UdypMR">有人会说，<b>其实目前方法的本质也还是根据执行轨迹，看错哪里了去针对性的改skill, 那吗我们采用贝叶斯方式建模这个过程的优势在哪里呢？</b></p><p data-pid="mSPmeWVz">这就得从机器学习书上贝叶斯派对比频率学派的优点说起了，简单来说就是：</p><blockquote data-pid="_NgVPkTn">Agent 每跑一个 case 都很贵：tokens 贵、latency 高、benchmark case 少、真实业务失败更少。<br>所以我们不能等到某个 failure mode 出现 100 次再统计。我们需要在 1 次、2 次、3 次失败后，就判断：要不要 patch？要不要继续观察？要不要压缩？要不要 retire？<br><b>在样本少、每个样本很贵、不能等到大样本统计稳定时，贝叶斯可以把先验、不确定性和新证据统一起来，做更稳健的决策。</b>这正是贝叶斯适合的地方。<br>它不会因为一次成功就过度相信，也不会因为一次失败就立刻判死刑。这对 Skill evolution 很重要，因为 LLM agent 的失败经常有随机性、环境性和任务偶然性。</blockquote><p data-pid="V9p6g6-J">所以，在我们的方法里，更适合的场景主要是这些：</p><figure data-size="normal"><img src="/assets/blog/images/5fad981f28853d94f2ee.png" data-caption="" data-size="normal" data-rawwidth="1486" data-rawheight="836" class="origin_image zh-lightbox-thumb" width="1486" data-original="/assets/blog/images/5fad981f28853d94f2ee.png"></figure><h2>总结</h2><p data-pid="DyYCVMSA">三门问题告诉我们：信息不是“看起来还剩几个选项”，而是“这个证据在不同假设下出现的概率是多少”。</p><p data-pid="FFKcKH4K">Bayesian Evidence Model 告诉我们：当证据由多个特征组成时，可以用一个可解释的 likelihood model，把每个特征对成功或失败的贡献统计出来；目前采用的是 factorized categorical likelihood，后续可以替换成更强的贝叶斯模型。</p><p data-pid="P7mTpyZL">人的后天学习告诉我们：技能不是一次性写死的规则，而是在经验、反馈和训练中不断校准的操作假设。</p><p data-pid="pmb17xgU">Bayesian-Agent 把这些思想落到 LLM Agent 工程里：</p><div class="highlight"><pre><code class="language-text"><span></span>Skill = hypothesis
Trajectory = evidence
Verifier = supervision
Evidence Model = posterior update
Context = non-parametric learned state
Next run = acquired learning in action
</code></pre></div><p data-pid="I0Zgl19P">这就是为什么我们认为 Skill/SOP 的进化会成为 Agent 工程里的核心能力。大模型已经足够聪明，但真正可靠的 Agent 还需要学会一件更基础也更困难的事：<b>从自己的成功经验和失败教训中，持续后天学习。</b></p>
