<p data-pid="VAAhdHl6">前两篇我们都在用这一行：</p><div class="highlight"><pre><code class="language-text"><span></span>sol = solve_ivp(...)
</code></pre></div><p data-pid="_FeNsUxt">如果教程停在这里，读者会很容易产生一种感觉：</p><p data-pid="8vb8zgaW"><b>我把方程交给一个函数，它把曲线吐出来；至于中间发生了什么，我只能相信它。</b></p><p data-pid="C0MZefa4">这就是“概念墙”。<br>这一篇专门拆这堵墙。</p><p data-pid="-Mz1LENg">我们不从数值分析术语开始，而从一个具体问题开始：</p><p data-pid="GZwwiOOh"><b>SIR 模型里，如果只知道今天的 <code>S</code>、<code>I</code>、<code>R</code>，电脑怎么一步步估计明天、后天、再后面的状态？</b></p><p data-pid="UAU42_F7">先给一句人话答案：</p><p data-pid="Lk2cJn4d"><b><code>solve_ivp</code> 会沿着时间轴试着往前走；每走一步都估计这一步准不准，准就接受，不准就把步子缩小重走。</b></p><p data-pid="LOWa4faX">这句话就是整篇文章的主线。</p><p data-pid="8BScG8cs">顺手把函数名也拆开：<code>solve_ivp</code> 里的 <code>ivp</code> 是 <code>initial value problem</code>，中文叫“初值问题”。<br>它解决的不是“所有微分方程”，而是这一类问题：</p><p data-pid="ChX3Km2W"><b>给我初始状态，再给我每个状态下的变化速度，我帮你把后面的轨迹算出来。</b></p><p data-pid="2cyxzcyo">这一节的 takeaway：<b><code>solve_ivp</code> 不是魔法函数，它是在解“给定起点以后怎么往前走”的问题。</b></p><h3>1. 先把问题摆到桌面上</h3><p data-pid="dSzDPjEa">我们继续用第二篇的 SIR 模型。</p><p data-pid="kmf0-NCH">SIR 是 <code>Susceptible-Infectious-Recovered</code> 的缩写：</p><ul>
<li data-pid="a9eGU7Ty">
<code>S</code>：Susceptible，易感者，还没感染、但可能被感染的人</li>
<li data-pid="DFbTkfbx">
<code>I</code>：Infectious，感染者，正在感染、也可能传给别人的人</li>
<li data-pid="5f3eV9kT">
<code>R</code>：Recovered，康复者，已经离开传播过程的人</li>
</ul><p data-pid="Iz5u8LYT">为了让数字更干净，下面用“人口比例”而不是“人数”：</p><ul>
<li data-pid="T1YiWQuo">
<code>S = 0.999</code> 表示 99.9% 的人还易感</li>
<li data-pid="CQjIUCdz">
<code>I = 0.001</code> 表示 0.1% 的人正在感染</li>
<li data-pid="hFetQrm1">
<code>R = 0.0</code> 表示暂时还没人康复</li>
<li data-pid="VQ7PVRtC">
<code>S + I + R = 1</code> 表示总人口比例为 1</li>
</ul><p data-pid="JRW7TMFk">时间单位取“天”。<br>参数也按“每天”理解：</p><ul>
<li data-pid="cpGC62Aa">
<code>beta = 0.32</code>：感染强度，越大表示感染者越容易把易感者拉进感染桶</li>
<li data-pid="P-CD-8zc">
<code>gamma = 0.10</code>：康复强度，越大表示感染者越快离开感染桶</li>
</ul><p data-pid="nhozUd54">现在的问题不是“曲线长什么样”，而是更小的一步：</p><p data-pid="ojv68C3K"><b>今天是 <code>S=0.999, I=0.001, R=0</code>，明天大概会变成什么？</b></p><p data-pid="CtBHeI25">这一节的 takeaway：<b>建模先要把变量、单位、初始状态说清楚；否则求解器算得再快，也不知道在算什么。</b></p><h3>2. 微分方程给的不是未来，而是“此刻速度”</h3><p data-pid="cqQByL_D">SIR 方程是：</p><p data-pid="mRBF8JWh"><img eeimg="2" src="/assets/blog/images/5fbf6847d556dd697227.svg" alt=" \begin{aligned} \frac{dS}{dt} &amp;= -\beta SI, \\ \frac{dI}{dt} &amp;= \beta SI - \gamma I, \\ \frac{dR}{dt} &amp;= \gamma I. \end{aligned} "></p><p data-pid="1VmZtMV4">这三行不要先当成形式化定义背。<br>先把它翻译成人话：</p><ul>
<li data-pid="HdCqZCwe">
<code>beta * S * I</code>：每天有多少易感者被感染者“拉进感染桶”</li>
<li data-pid="z5CLhj_W">
<code>-beta * S * I</code>：这些人从 <code>S</code> 桶离开，所以 <code>S</code> 减少</li>
<li data-pid="jx032gWj">
<code>+beta * S * I</code>：同一批人进入 <code>I</code> 桶，所以 <code>I</code> 增加</li>
<li data-pid="cZYv8zBx">
<code>gamma * I</code>：每天有多少感染者康复</li>
<li data-pid="nnCL26Jr">
<code>-gamma * I</code>：这些人从 <code>I</code> 桶离开，所以 <code>I</code> 减少</li>
<li data-pid="VJI2QM3J">
<code>+gamma * I</code>：同一批人进入 <code>R</code> 桶，所以 <code>R</code> 增加</li>
</ul><p data-pid="yECUYx0U">所以 <code>dS_dt</code>、<code>dI_dt</code>、<code>dR_dt</code> 不是明天的 <code>S</code>、<code>I</code>、<code>R</code>。<br>它们只是“现在这一刻三个桶变化得有多快”。</p><p data-pid="azKksyBc">代码里就是这个函数：</p><div class="highlight"><pre><code class="language-text"><span></span>def sir_rhs(t, y, beta, gamma):
    """给定当前时刻和当前状态，返回 S、I、R 的当前变化速度。"""
    # y 是当前状态，不是完整曲线。
    S, I, R = y

    # 感染流：S 桶流向 I 桶。
    infection = beta * S * I

    # 康复流：I 桶流向 R 桶。
    recovery = gamma * I

    # 三个导数就是三个桶的净流入速度。
    dS_dt = -infection
    dI_dt = infection - recovery
    dR_dt = recovery

    return [dS_dt, dI_dt, dR_dt]
</code></pre></div><p data-pid="VMHJTZS-">这里 <code>rhs</code> 是 <code>right-hand side</code> 的缩写，意思是“方程右边”。<br>这个名字听起来像术语，但它在代码里只做一件事：</p><p data-pid="bEbfrSJ3"><b>输入当前状态，输出当前变化速度。</b></p><p data-pid="MDuQftDO">这一节的 takeaway：<b>微分方程不直接给未来曲线，它只告诉你“站在当前点，下一瞬间往哪儿走”。</b></p><h3>3. 先手算一天，看看电脑到底在重复什么</h3><p data-pid="1TowYiMH">用第二篇同一组参数：</p><div class="highlight"><pre><code class="language-text"><span></span>beta = 0.32
gamma = 0.10
S = 0.999
I = 0.001
R = 0.0
</code></pre></div><p data-pid="eFHU0f8n">先算感染流：</p><p data-pid="qvIF94RE"><img eeimg="2" src="/assets/blog/images/80ec077c46402cf10a52.svg" alt=" \beta SI = 0.32 \times 0.999 \times 0.001 = 0.00031968 "></p><p data-pid="joXKjZ3z">再算康复流：</p><p data-pid="Nr8ExuaG"><img eeimg="2" src="/assets/blog/images/72af6c7a7a4c9a98fa3b.svg" alt=" \gamma I = 0.10 \times 0.001 = 0.0001 "></p><p data-pid="2Us_dIPD">所以当前三个变化速度是：</p><p data-pid="cRFPH9M9"><img eeimg="2" src="/assets/blog/images/33438ccc8a2ded28f80a.svg" alt=" \begin{aligned} \frac{dS}{dt} &amp;= -0.00031968, \\ \frac{dI}{dt} &amp;= 0.00031968 - 0.0001 = 0.00021968, \\ \frac{dR}{dt} &amp;= 0.0001. \end{aligned} "></p><p data-pid="izKSr6bU">这说明在第一天刚开始的时候：</p><ul>
<li data-pid="sy-Pzd9k">
<code>S</code> 正在减少</li>
<li data-pid="rXf-EEOe">
<code>I</code> 正在增加</li>
<li data-pid="Cz9dLRYJ">
<code>R</code> 正在增加</li>
</ul><p data-pid="nmDgNcW4">如果先用最朴素的“一天后约等于今天加一天的变化量”，就得到：</p><p data-pid="2hOs3S7U"><img eeimg="2" src="/assets/blog/images/e098d6ead12e7d319f44.svg" alt=" y_{\text{next}} \approx y + h f(t, y) "></p><p data-pid="Ai3mDEMD">这里：</p><ul>
<li data-pid="S2Lv5PJx">
<code>y</code> 是当前状态 <code>[S, I, R]</code>
</li>
<li data-pid="dZEyUfj7">
<code>f(t, y)</code> 是当前变化速度</li>
<li data-pid="gaWdd3q7">
<code>h</code> 是这一步走多长时间</li>
</ul><p data-pid="tC_S78Pw">取 <code>h = 1</code> 天：</p><div class="highlight"><pre><code class="language-text"><span></span>import numpy as np

beta = 0.32
gamma = 0.10
y = np.array([0.999, 0.001, 0.0])
h = 1.0

S, I, R = y
dy = np.array([
    -beta * S * I,
    beta * S * I - gamma * I,
    gamma * I,
])

y_next = y + h * dy
print(y_next)
</code></pre></div><p data-pid="bJXbpBcm">大概是：</p><div class="highlight"><pre><code class="language-text"><span></span>[0.99868032 0.00121968 0.0001    ]
</code></pre></div><p data-pid="fjDeqlk3">这一小段就是数值求解的第一性原理：</p><p data-pid="OsD5CK6B"><b>看当前速度，往前挪一小步。</b></p><p data-pid="HGVgdIh_">这一节的 takeaway：<b>电脑算微分方程并不是一次看穿未来，而是反复做“看当前速度，往前走一点”。</b></p><h3>4. 为什么不能一直用这个最朴素方法</h3><p data-pid="nmw5WS40">上面这个方法通常叫欧拉法。<br>欧拉法的一句话解释是：</p><p data-pid="-c9nW1iJ"><b>只看起点斜率，然后用这条直线近似下一小段曲线。</b></p><p data-pid="61EhNqFC">它的优点是直观。<br>它的问题也很直观：</p><p data-pid="2TZhomBY"><b>如果一步太大，曲线中间已经弯了，你还拿起点斜率一路冲过去，误差就会变大。</b></p><p data-pid="mIRqVuy3">SIR 曲线尤其容易出现这个问题。<br>在疫情初期，<code>I(t)</code> 增长越来越快；到达峰值附近以后，<code>I(t)</code> 又开始转弯往下。<br>这些地方曲线不是一条直线。</p><p data-pid="1_wZF8qo">所以真正的求解器需要回答两个问题：</p><ol>
<li data-pid="8f8dWsxa">这一步能不能走得更准一点？</li>
<li data-pid="0v2JzPzb">这一步到底该走多大？</li>
</ol><p data-pid="55s4PcUs"><code>solve_ivp</code> 默认使用的 <code>RK45</code>，就是围绕这两个问题设计的。</p><p data-pid="F3lQqAjw">这一节的 takeaway：<b>欧拉法给了直觉，但真实求解器还要处理“曲线会弯”和“步子该多大”这两个问题。</b></p><h3>5. <code>RK45</code> 不是新墙，它只是“多看几个斜率”</h3><p data-pid="qd6ePoTp"><code>RK45</code> 里的 <code>RK</code> 是 <code>Runge-Kutta</code>。<br>不要先背人名。先记住它解决的问题：</p><p data-pid="Nul6g7Yo"><b>一步里面只看起点斜率太粗，那就多看几个中间斜率。</b></p><p data-pid="ltFkL6zv">你可以把一次试步想成这样：</p><div class="highlight"><pre><code class="language-text"><span></span>起点斜率       k1 = f(t, y)
往前探一点     k2 = f(t + 一小段, y + 用 k1 估出来的中间状态)
再往前探一点   k3 = f(t + 另一小段, y + 用前面斜率估出来的中间状态)
继续探         ...
综合这些斜率   y_new = y + h * 加权平均斜率
</code></pre></div><p data-pid="EFHzbyTA">这里的 <code>k1, k2, k3, ...</code> 仍然只是变化速度。<br>区别是：欧拉法只问一次“现在往哪儿走”，Runge-Kutta 方法会在一步内部多问几次“如果走到中间，方向会不会变”。</p><p data-pid="59_fCTr7">这样它对弯曲的轨迹更敏感。</p><p data-pid="0MEAtyRq"><code>RK45</code> 里的 <code>45</code> 表示它在同一次试步里会构造两个答案：</p><ul>
<li data-pid="Bq6VAqZ4">一个四阶精度的答案</li>
<li data-pid="-znAsRNn">一个五阶精度的答案</li>
</ul><p data-pid="GUtmiWhN">“阶”这个词也可以先用人话理解：</p><p data-pid="yHme--sZ"><b>步长变小时，高阶方法的误差下降得更快。</b></p><p data-pid="gIlWPwpN">这里不需要展开完整系数表。<br>对建模使用者来说，最重要的是：</p><p data-pid="lhM1yRJF"><b><code>RK45</code> 一边尝试前进一步，一边顺手得到了一个误差估计。</b></p><p data-pid="wNceNYiP">如果你去看 SciPy 文档，会看到 <code>Dormand-Prince</code> 这个名字。<br>它不是新概念墙，可以先把它理解成：<b>RK45 具体使用的一张固定系数表，规定每个中间斜率在哪里算、最后怎么加权。</b></p><p data-pid="VUspD__1">这一节的 takeaway：<b>RK45 的核心不是名字，而是“多看几个斜率，并在同一步里估计误差”。</b></p><h3>6. 它怎么知道这一步准不准</h3><p data-pid="kNsWalCS">假设 <code>RK45</code> 从 <code>t</code> 试着走到 <code>t + h</code>。<br>它会在同一步里得到两个候选结果：</p><p data-pid="JH47Y88p"><img eeimg="2" src="/assets/blog/images/c7c8eaf705845f96118a.svg" alt=" y_4 \quad \text{和} \quad y_5 "></p><p data-pid="qR4LJZ2C">可以先把它们理解成：</p><ul>
<li data-pid="6RplPm0U">
<code>y4</code>：保守一点的估计</li>
<li data-pid="3Z5BJb7B">
<code>y5</code>：更高阶一点的估计</li>
</ul><p data-pid="Pgcb_Ewm">如果 <code>y4</code> 和 <code>y5</code> 很接近，说明这一段曲线比较容易估，这一步大概率可信。<br>如果 <code>y4</code> 和 <code>y5</code> 差很多，说明这一步太冒进了，应该缩小步长重算。</p><p data-pid="RwOpEOLE">这就是误差估计的来源：</p><p data-pid="hw5PaQy-"><img eeimg="2" src="/assets/blog/images/7d4d7c89ae48ba6483eb.svg" alt=" \text{error} \approx |y_5 - y_4| "></p><p data-pid="bTJYBi0V">注意，这个误差不是“和真实答案的差”。<br>真实答案我们本来就不知道。<br>它是用两个不同精度的近似结果互相校验。</p><p data-pid="T5xrrpbQ">这一节的 takeaway：<b>数值求解器不是知道真实答案，而是用两个近似答案的差来判断这一步靠不靠谱。</b></p><h3>7. <code>rtol</code> 和 <code>atol</code> 是误差预算</h3><p data-pid="s1HP7k3s">有了误差估计，还需要一个判断标准：</p><p data-pid="r3ZbiK2d"><b>差多少算可以接受？</b></p><p data-pid="pogaK-eF">SciPy 对每个变量大致用这个尺度：</p><p data-pid="ryrbiMsA"><img eeimg="2" src="/assets/blog/images/addb1f3a0394bcc23a56.svg" alt=" \text{允许误差} = \text{atol} + \text{rtol} \times |y| "></p><p data-pid="idd6JNhh">两个名字展开一下：</p><ul>
<li data-pid="B-eneTDE">
<code>atol</code>：absolute tolerance，绝对容差</li>
<li data-pid="M4kqOHNc">
<code>rtol</code>：relative tolerance，相对容差</li>
</ul><p data-pid="fAFGPHzV">人话解释：</p><ul>
<li data-pid="RQOwKWT0">
<code>atol</code> 管变量很小时的最低精度要求</li>
<li data-pid="AGmbZewJ">
<code>rtol</code> 管变量变大以后的相对精度要求</li>
</ul><p data-pid="2gZaImS9">为什么要两个？<br>看 SIR 里的 <code>I(t)</code> 就知道了。</p><p data-pid="CfEHzVSX">疫情刚开始时，<code>I = 0.001</code> 很小。<br>如果只用相对误差，分母太小，判断会变得很敏感；<code>atol</code> 可以兜底。</p><p data-pid="DxV0O9wL">疫情中期，<code>I</code> 可能涨到 0.3 左右。<br>这时绝对误差 <code>1e-9</code> 已经太小了，主要由 <code>rtol * |I|</code> 来决定“相对上够不够准”。</p><p data-pid="PldXgHCc">所以容差不是代码装饰。<br>它直接影响求解器敢不敢迈大步。</p><p data-pid="dyEbW3e6">这一节的 takeaway：<b><code>rtol</code> 和 <code>atol</code> 是你给求解器的误差预算；预算越小，求解器通常走得越谨慎。</b></p><h3>8. 步长为什么会自己变</h3><p data-pid="fn1ux_T4">现在把一次内部试步写成伪代码：</p><div class="highlight"><pre><code class="language-text"><span></span>给定当前 t、当前 y、当前步长 h

试着用 RK45 从 t 走到 t + h
得到 y5 和 y4
用 |y5 - y4| 估计误差
把误差和 atol + rtol * |y| 比较

如果误差在预算内：
    接受这一步
    t 变成 t + h
    y 变成 y5
    如果误差很小，下一步可以把 h 调大

如果误差超预算：
    拒绝这一步
    把 h 调小
    重新试
</code></pre></div><p data-pid="VDFgnpXD">这就是“自适应步长”。<br>这个词如果直接扔出来会像概念墙，但它的人话解释很简单：</p><p data-pid="tpXWsGoW"><b>路平就大步走，路弯就小步走；走错了就退回来换小步。</b></p><p data-pid="N0up8uE-">在 SIR 里，步长变化也有现实含义：</p><ul>
<li data-pid="Ukna1l5G">刚开始 <code>I</code> 很小，但指数增长迹象开始出现，求解器会谨慎起步</li>
<li data-pid="KfV2vcvI">传播中期曲线变化快，步长不能太粗</li>
<li data-pid="e63sq-UU">后期 <code>I</code> 逐渐接近 0，曲线变平，求解器可以走大步</li>
</ul><p data-pid="PiZcEdZQ">这一节的 takeaway：<b>步长不是你随便指定一个固定值，而是求解器根据误差预算动态选择的。</b></p><figure data-size="normal"><img src="/assets/blog/images/c7baf043709b11f7803d.png" data-caption="" data-size="normal" data-rawwidth="1600" data-rawheight="900" class="origin_image zh-lightbox-thumb" width="1600" data-original="/assets/blog/images/c7baf043709b11f7803d.png"></figure><p><br></p><p data-pid="WZ3_84Ty">这张解释图对应 <code>RK45</code> 的内部动作：先试走一步，再拿误差和预算对照，最后决定接受步长还是缩小重试。</p><h3>9. <code>solve_ivp</code> 这一层到底包了什么</h3><p data-pid="duXD6Gb-">现在再回头看 <code>solve_ivp</code>：</p><div class="highlight"><pre><code class="language-text"><span></span>sol = solve_ivp(
    lambda t, y: sir_rhs(t, y, beta, gamma),
    (0, 160),
    [0.999, 0.001, 0.0],
    method="RK45",
    rtol=1e-8,
    atol=1e-11,
)
</code></pre></div><p data-pid="E0hSI4ri">每个参数都可以用问题语言解释：</p><ul>
<li data-pid="eHbz-4AQ">第一项 <code>lambda t, y: ...</code>：告诉求解器“给定当前状态时，变化速度怎么算”</li>
<li data-pid="_vtgXEPn">
<code>(0, 160)</code>：从第 0 天算到第 160 天</li>
<li data-pid="Bt2fXLHm">
<code>[0.999, 0.001, 0.0]</code>：初始状态，也就是初值问题里的“初值”</li>
<li data-pid="YXkt_ynQ">
<code>method="RK45"</code>：内部用 RK45 试步、估误差、调步长</li>
<li data-pid="_gN2W5Ki">
<code>rtol=1e-8, atol=1e-11</code>：误差预算</li>
</ul><p data-pid="X_2CEP0h">这段代码没有说“每天算一次”。<br>它只说：从 0 算到 160，误差按这个标准控制。</p><p data-pid="RUjdTg04">具体中间走了多少步，是 <code>RK45</code> 自己决定的。</p><p data-pid="1bzQ8GjU">这一节的 takeaway：<b><code>solve_ivp</code> 是一个调度入口，真正反复做试步的是里面的数值方法。</b></p><h3>10. <code>t_eval</code> 是拍照点，不是脚印</h3><p data-pid="B7Y_KXEl">我们经常会加上：</p><div class="highlight"><pre><code class="language-text"><span></span>t_eval = np.linspace(0, 160, 800)

sol = solve_ivp(
    lambda t, y: sir_rhs(t, y, beta, gamma),
    (0, 160),
    [0.999, 0.001, 0.0],
    t_eval=t_eval,
    method="RK45",
)
</code></pre></div><p data-pid="2lmK3kHx">很多人会自然以为：</p><p data-pid="p8Bn0Cg3"><b><code>solve_ivp</code> 内部就是按照这 800 个点一步一步算的。</b></p><p data-pid="YIsjRbm8">这其实是错的。</p><p data-pid="MUeGgiHY"><code>t_eval</code> 只表示：</p><p data-pid="cPDf-a9M"><b>最后请把结果报告在这些时间点上。</b></p><p data-pid="eQNxJpTO">内部真实接受过哪些步子，仍然由误差控制决定。</p><p data-pid="jE0KNttX">可以这样记：</p><ul>
<li data-pid="STOWX5u1">内部步子是脚印</li>
<li data-pid="8NnEJhdI">
<code>t_eval</code> 是你想拿到照片的位置</li>
</ul><p data-pid="Udk4fTth">如果照片位置不在脚印上，求解器会在已接受的内部步子之间做插值。<br>插值不是重新解方程，而是在已经算好的局部轨迹上补出你要看的时间点。</p><p data-pid="tS9bDaQe">这一节的 takeaway：<b><code>t_eval</code> 控制输出密度，不等于控制内部计算步长。</b></p><h3>11. 用低层 <code>RK45</code> 把脚印拿出来</h3><p data-pid="FreK6uz7">如果只用 <code>solve_ivp</code>，你通常看到的是整理好的输出。<br>如果想观察内部脚印，可以直接用 SciPy 的低层 <code>RK45</code> 类。</p><p data-pid="4lnyDte3">下面这段代码和正文是一一对应的：</p><div class="highlight"><pre><code class="language-text"><span></span>from scipy.integrate import RK45

solver = RK45(
    lambda t, y: sir_rhs(t, y, beta, gamma),
    0.0,                          # 初始时间
    np.array([0.999, 0.001, 0.0]), # 初始状态
    160.0,                        # 终止时间
    rtol=1e-6,
    atol=1e-9,
)

ts = [solver.t]
ys = [solver.y.copy()]
steps = []

while solver.status == "running":
    solver.step()              # 内部完成：试步、估误差、接受或缩小重试
    ts.append(solver.t)        # 接受后的真实时间点
    ys.append(solver.y.copy()) # 接受后的真实状态
    steps.append(solver.step_size) # 刚刚接受的步长
</code></pre></div><p data-pid="jPW1uFz1">这段循环最值得看的不是类名，而是三个量：</p><ul>
<li data-pid="VYEkjIeV">
<code>solver.t</code>：求解器真正走到的时间</li>
<li data-pid="yki5fCVF">
<code>solver.y</code>：这个真实时间上的状态</li>
<li data-pid="OD5d4ZLA">
<code>solver.step_size</code>：刚刚被接受的那一步有多长</li>
</ul><p data-pid="cbR1ZOOf">有了这些量，<code>solve_ivp</code> 的黑箱就被打开了一条缝。</p><p data-pid="VMs2hCUr">这一节的 takeaway：<b><code>solve_ivp</code> 适合日常求解，低层 <code>RK45</code> 适合观察求解器内部怎么走。</b></p><h3>12. 图里能看到什么</h3><p data-pid="71v2hLUo">运行配套脚本：</p><div class="highlight"><pre><code class="language-text"><span></span>python 03_solve_ivp_inside_demo.py
</code></pre></div><p data-pid="7doYTS3q">会生成这张图：</p><figure data-size="normal"><img src="/assets/blog/images/1cb9eb3ec44217173142.png" data-caption="" data-size="normal" data-rawwidth="2816" data-rawheight="1056" class="origin_image zh-lightbox-thumb" width="2816" data-original="/assets/blog/images/1cb9eb3ec44217173142.png"></figure><p><br></p><p data-pid="rkaC2HSB">左图对比的是：</p><ul>
<li data-pid="tOkX4FRm">橙色线：<code>solve_ivp</code> 最后报告给你的 <code>I(t)</code> 输出曲线</li>
<li data-pid="T34R8Q1c">蓝色点：宽松容差下，<code>RK45</code> 内部真正接受过的点</li>
<li data-pid="tkxEIECG">黑色虚线：感染者比例峰值附近的位置</li>
</ul><p data-pid="psxm6FZW">右图对比的是：</p><ul>
<li data-pid="6A0HxMUT">
<code>rtol=1e-6</code>：误差预算宽松，内部接受步数少，步长较大</li>
<li data-pid="jmh22lXY">
<code>rtol=1e-10</code>：误差预算严格，内部接受步数多，步长较小</li>
</ul><p data-pid="niGbrmnG">脚本输出类似：</p><div class="highlight"><pre><code class="language-text"><span></span>saved: /Volumes/PSSD/code/Mathematical_Modeling/projects/python_differential_equations/figures/rk45_inside_sir.png

RK45 loose steps: 60, min=0.0411, max=5.3161
RK45 tight steps: 361, min=0.0065, max=1.0650

max population error = 1.11e-15
R_eff at output peak = 0.9946

</code></pre></div><p data-pid="C7NaD0qC">这里最重要的对比是：</p><p data-pid="Ew502R-f"><b>输出点有 800 个，不代表内部走了 800 步。</b></p><p data-pid="QUGTHtbD">宽松容差下，内部只接受了约 60 步。<br>严格容差下，内部接受了约 361 步。<br>但你仍然可以拿到 800 个 <code>t_eval</code> 输出点，因为输出点可以由内部轨迹插值得到。</p><p data-pid="-FxzD7a_">这一节的 takeaway：<b>输出越密，不一定计算越细；真正决定计算细不细的是误差预算和内部步长。</b></p><h3>13. 回到建模：怎么知道结果没乱跑</h3><p data-pid="JDxIQMml">会调用求解器只是第一层。<br>建模时还要会检查结果。</p><p data-pid="grIWlOEj">SIR 有一个很自然的守恒检查：</p><p data-pid="2fuC1GhE"><img eeimg="2" src="/assets/blog/images/612999ce15b7fd27c62c.svg" alt=" S(t) + I(t) + R(t) \approx 1 "></p><p data-pid="-etR2WaJ">原因是模型里没有出生、死亡、外来人口。<br>人只是从 <code>S</code> 流向 <code>I</code>，再从 <code>I</code> 流向 <code>R</code>，总量不应该凭空变多或变少。</p><p data-pid="xpcOALMR">代码里可以这样检查：</p><div class="highlight"><pre><code class="language-text"><span></span>population_error = np.max(np.abs(sol.y.sum(axis=0) - 1.0))
print(f"max population error = {population_error:.2e}")
</code></pre></div><p data-pid="vocPcfVZ">还可以检查感染峰值。</p><p data-pid="hmx_l-bX">第二篇讲过，基本再生数是：</p><p data-pid="bI5UCItw"><img eeimg="2" src="/assets/blog/images/2f077e9dab107fef7895.svg" alt=" \mathcal{R}_0 = \frac{\beta}{\gamma} "></p><p data-pid="mGzQljz3">但疫情是不是还在增长，不只看固定的 <img eeimg="1" src="/assets/blog/images/a1c124a3ed7c7e409dcf.svg" alt="\mathcal{R}_0">，还要看当时剩下多少易感者：</p><p data-pid="AIh6QEku"><img eeimg="2" src="/assets/blog/images/143dae99ca85948f92d9.svg" alt=" \mathcal{R}_{\mathrm{eff}}(t) = \frac{\beta}{\gamma} S(t) "></p><p data-pid="iyea4E8L">当感染者达到峰值时，<code>I(t)</code> 的变化速度接近 0：</p><p data-pid="SseEJgpk"><img eeimg="2" src="/assets/blog/images/d67ba25d3309ce495067.svg" alt=" \frac{dI}{dt} = \beta SI - \gamma I \approx 0 "></p><p data-pid="j_rRpcVh">如果 <code>I &gt; 0</code>，两边除以 <code>I</code>：</p><p data-pid="C6uE5Alk"><img eeimg="2" src="/assets/blog/images/9f1232530db2d1a0d826.svg" alt=" \beta S - \gamma \approx 0 "></p><p data-pid="ap_7L8yl">也就是：</p><p data-pid="Gvcrs_GJ"><img eeimg="2" src="/assets/blog/images/3544bad8fdbc9e0cc065.svg" alt=" \frac{\beta}{\gamma}S(t) \approx 1 "></p><p data-pid="sj2XDudw">所以峰值附近可以检查：</p><div class="highlight"><pre><code class="language-text"><span></span>I = sol.y[1]
peak_idx = np.argmax(I)
S_at_peak = sol.y[0, peak_idx]
R_eff_at_peak = beta / gamma * S_at_peak

print(f"R_eff at output peak = {R_eff_at_peak:.4f}")
</code></pre></div><p data-pid="eC72GUJJ">这个检查不要求正好等于 1。<br>因为我们是在离散输出点里找峰值，真正的连续峰值可能落在两个输出点之间。<br>但它应该接近 1。</p><p data-pid="UIgi_-bo">这一节的 takeaway：<b>不要只看图漂不漂亮，要用模型自身的结构做 sanity check。</b></p><h3>14. 什么时候该对 <code>solve_ivp</code> 提高警惕</h3><p data-pid="nPQatXOz">这篇不是要把你变成数值分析专家，而是让你知道哪里可能出问题。</p><p data-pid="tX2JmNYO">实际建模里，下面几种情况要多看一眼：</p><ul>
<li data-pid="CwCCeI-X">
<code>sol.success</code> 是 <code>False</code>：求解器明确说没成功</li>
<li data-pid="ntN6Bv_1">
<code>S</code>、<code>I</code>、<code>R</code> 出现明显负数：模型或容差可能有问题</li>
<li data-pid="uPX4P9Mf">
<code>S + I + R</code> 明显偏离 1：右端函数或数值精度可能有问题</li>
<li data-pid="Zxt4KcW7">改小 <code>rtol</code>、<code>atol</code> 后结果变化很大：原来的容差可能太松</li>
<li data-pid="etIqDnDv">步长长期被压得极小：模型可能变化尺度差异很大，需要换方法或重新缩放变量</li>
</ul><p data-pid="L9BTIo4t">最后一条有时会牵出“刚性方程”这个术语。<br>先不用急着背。<br>人话理解就是：</p><p data-pid="2GlFcfeG"><b>系统里有的量变化特别快，有的量变化特别慢，显式一步步试走的方法会被快变量拖住。</b></p><p data-pid="JnDN5dTS">遇到这种情况，再去看 <code>Radau</code>、<code>BDF</code> 这类方法就有动机了。</p><p data-pid="M4ACQ_XY">这一节的 takeaway：<b>知道 <code>solve_ivp</code> 怎么走，你才知道什么时候该信它、什么时候该检查它。</b></p><h3>15. 小结</h3><p data-pid="M-jGHuWV">把这一篇压成一句话：</p><p data-pid="ieME_-pT"><b><code>solve_ivp</code> 是在解初值问题：从初始状态出发，用右端函数给出的当前变化速度，一步步试走、估误差、调步长，最后把结果报告到你要看的时间点。</b></p><p data-pid="L1xWPoMV">如果只记六句话，就记这六句：</p><ul>
<li data-pid="RbhShrgV">
<code>ivp</code> 是 <code>initial value problem</code>，核心是“给起点，往后推”</li>
<li data-pid="EdkDNZsm">SIR 的方程右边返回的是当前变化速度，不是未来答案</li>
<li data-pid="aXQis9gv">最朴素的数值思想是 <code>y_next = y + h * f(t, y)</code>
</li>
<li data-pid="8XFXLZLI">
<code>RK45</code> 在一步里多看几个斜率，并用四阶/五阶两个结果估误差</li>
<li data-pid="398d-ZcD">
<code>rtol</code> 和 <code>atol</code> 是误差预算，决定步长能不能放大</li>
<li data-pid="8kSs8Ewq">
<code>t_eval</code> 是输出拍照点，不是求解器内部脚印</li>
</ul><p data-pid="N_v_O6hV">下一篇如果继续写，我们就可以用这个理解去看 <code>Lotka-Volterra</code> 捕食-被捕食模型。<br>到那时，相图里的每一个箭头，本质上还是一句话：</p><p data-pid="n-rc3JJ-"><b>当前状态告诉你下一步往哪里走。</b></p><h3>参考</h3><ul>
