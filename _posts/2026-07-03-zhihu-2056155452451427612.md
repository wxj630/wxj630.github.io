<p data-pid="Rt4NnaXr">前面几篇文章里，我主要在讲 Bayesian-Agent 为什么需要贝叶斯、它和 frequentist skill evolving 的区别、没有手写 skill catalog 的 zero-shot 模式是否仍然有效。</p><p data-pid="T9ukPq16">这篇文章换一个角度，回答一个更工程化的问题：</p><p data-pid="KwYLDogo"><b>如果我已经有自己的 agent 了，怎么快速接入 Bayesian-Agent？</b></p><blockquote data-pid="eaQk1XIg">论文地址：<a href="http://link.zhihu.com/?target=http%3A//arxiv.org/abs/2606.08348" data-icon-name="zhicon_icon_24_link" class=" external" target="_blank" rel="nofollow noreferrer"><span class="invisible">http://</span><span class="visible">arxiv.org/abs/2606.0834</span><span class="invisible">8</span><span class="ellipsis"></span></a><br>GitHub：<a href="http://link.zhihu.com/?target=https%3A//github.com/DataArcTech/Bayesian-Agent" data-icon-name="zhicon_icon_24_link" class=" external" target="_blank" rel="nofollow noreferrer"><span class="invisible">https://</span><span class="visible">github.com/DataArcTech/</span><span class="invisible">Bayesian-Agent</span><span class="ellipsis"></span></a>
</blockquote><p data-pid="OWpA3mGD">答案其实很简单：</p><p data-pid="CJj788mX">你不需要换掉自己的 agent，也不需要把自己的 harness 重写成 Bayesian-Agent 的样子。</p><p data-pid="xnM9bjta">你只需要让自己的 agent 多做两件事：</p><ol>
<li data-pid="sN87wWBL">接收 Bayesian-Agent 给出的 Skill/SOP context；</li>
<li data-pid="7rQYpXSM">把每次运行后的 trajectory、token、成功失败、failure mode 等信息返回给 Bayesian-Agent。</li>
</ol><p data-pid="Ox9oIVFj">也就是说，Bayesian-Agent 更准确地说不是“又一个 agent framework”，而是一个：</p><div class="highlight"><pre><code class="language-text"><span></span>Bayesian-Agent Skill Evolution Layer
</code></pre></div><p data-pid="_b2uAQJA">它可以挂在你已有的 agent / harness 旁边，依赖之前的执行轨迹，不断更新 skill belief，再把下一轮更有针对性的 skill context 交还给你的 agent。</p><h2>一、最重要的心智模型：不要替换你的 agent，而是加一层 evolution layer</h2><p data-pid="P4OiwMRb">很多 agent 框架都已经很复杂了。</p><p data-pid="630I6IES">它们可能有自己的：</p><ul>
<li data-pid="XNjILrM1">tool system；</li>
<li data-pid="JQ3Z1jAX">memory；</li>
<li data-pid="NOi0AK6O">planner；</li>
<li data-pid="XOQV54Bd">browser/runtime；</li>
<li data-pid="8mk10h1b">workspace；</li>
<li data-pid="BsF1Kf2E">permission model；</li>
<li data-pid="K3lt8Pay">prompt template；</li>
<li data-pid="r1EI4ODE">logging/tracing；</li>
<li data-pid="UTK8c511">benchmark runner。</li>
</ul><p data-pid="LLBJllXU">如果 Bayesian-Agent 要求你把这些全部迁移过来，那上手成本就太高了。</p><p data-pid="dOlRPO7g">所以我们一开始就把 Bayesian-Agent 设计成分层结构：</p><div class="highlight"><pre><code class="language-text"><span></span>你的 Agent / Harness
        |
        | 运行任务，产生 trajectory
        v
Bayesian-Agent Evidence Layer
        |
        | success / failure / tokens / failure mode / metadata
        v
Bayesian Skill Registry
        |
        | posterior belief + rewrite policy
        v
Skill/SOP Context
        |
        | 注入下一次任务
        v
你的 Agent / Harness
</code></pre></div><p data-pid="AY0jgyc6">这件事的关键是：<b>Bayesian-Agent 不需要控制你的 agent 内部所有细节。</b></p><p data-pid="rX4pZrle">它只需要一个稳定边界：</p><div class="highlight"><pre><code class="language-text"><span></span>run(task, skill_context) -&gt; trajectory-like result
</code></pre></div><p data-pid="ooWbWAoD">这就是 adapter。</p><h2>二、Adapter 到底要做什么？</h2><p data-pid="I1EskreS">Bayesian-Agent 里的 adapter contract 非常小。</p><p data-pid="a02Jc2en">大概就是：</p><div class="highlight"><pre><code class="language-text"><span></span>from typing import Any, Mapping, Protocol

class AgentAdapter(Protocol):
    def run(
        self,
        task: Mapping[str, Any],
        skill_context: str,
    ) -&gt; Mapping[str, Any]:
        ...
</code></pre></div><p data-pid="HYgb6UfT">它接收两个东西：</p><ul>
<li data-pid="psU80r0g">
<code>task</code>：你的 benchmark 或业务任务；</li>
<li data-pid="_D8lAdG8">
<code>skill_context</code>：Bayesian-Agent 根据历史证据生成的 Skill/SOP context。</li>
</ul><p data-pid="KsM1r0ki">它返回一个 trajectory-like mapping，例如：</p><div class="highlight"><pre><code class="language-text"><span></span>{
    "task_id": "sop_12",
    "success": False,
    "transcript": "...",
    "input_tokens": 70123,
    "output_tokens": 4242,
    "total_tokens": 74365,
    "turns": 8,
    "elapsed_seconds": 31.5,
    "failure_mode": "left_expected_output_blank",
    "summary": "The model left the expected_output cell blank.",
    "metadata": {
        "harness": "my_agent",
        "model": "deepseek-v4-flash"
    }
}
</code></pre></div><p data-pid="hy9_AGzV">这些字段不需要一开始就全部完美。</p><p data-pid="w2ZXx60O">最低限度，你至少要能提供：</p><ul>
<li data-pid="jMJzp04m">
<code>task_id</code>：是哪一个任务；</li>
<li data-pid="Bw1Iu2H-">
<code>success</code>：是否通过 verifier / grader / 业务检查；</li>
<li data-pid="FFI4wTaz">
<code>transcript</code> 或运行日志：方便后续归因；</li>
<li data-pid="UFXLWTiD">token usage：方便计算效率；</li>
<li data-pid="1o9whvyQ">failure mode：如果没有手写 taxonomy，也可以先让 Bayesian-Agent 自动发现。</li>
</ul><p data-pid="N3neIfCr">Bayesian-Agent 会把这些运行结果转成 <code>TrajectoryEvidence</code>，再更新 Skill belief。</p><h2>三、最小 adapter 怎么写？</h2><p data-pid="pe5hhnh_">假设你已经有一个自己的 agent：</p><div class="highlight"><pre><code class="language-text"><span></span>my_agent.run(prompt, workspace=workspace)
</code></pre></div><p data-pid="PTjdAqKZ">那 adapter 可以非常薄：</p><div class="highlight"><pre><code class="language-text"><span></span>from dataclasses import dataclass
from typing import Any, Mapping


@dataclass
class MyAgentAdapter:
    agent: Any

    def run(self, task: Mapping[str, Any], skill_context: str = "") -&gt; Mapping[str, Any]:
        prompt = str(task["prompt"])
        if skill_context:
            prompt = f"{skill_context}\n\n{prompt}"

        result = self.agent.run(
            prompt,
            workspace=task["workspace"],
        )

        return {
            "task_id": task.get("task_id", ""),
            "transcript": result.transcript,
            "input_tokens": result.input_tokens,
            "output_tokens": result.output_tokens,
            "total_tokens": result.total_tokens,
            "elapsed_seconds": result.elapsed_seconds,
            # success / failure_mode 可以由外部 verifier 或 benchmark runner 补上
        }
</code></pre></div><p data-pid="J6OcYY4w">注意这里的 adapter 不应该做太多事。</p><p data-pid="Z6vxI41E"><b>也就是说 adapter 的 return 重点是：轨迹、token、耗时、错误信息。</b></p><p data-pid="pquGXIa8"><b><code>success/failure_mode</code> 通常是 verifier 之后由BA再加上去的。</b></p><p data-pid="_oCqpV6l">它不应该负责：</p><ul>
<li data-pid="dtBOEs-w">benchmark loop；</li>
<li data-pid="Ae1YZXNA">grader；</li>
<li data-pid="TMceO47M">Bayesian posterior update；</li>
<li data-pid="WJXXHtDP">skill registry；</li>
<li data-pid="nTTxih__">incremental repair 策略；</li>
<li data-pid="P56fht7d">复杂的实验统计。</li>
</ul><p data-pid="tew47J3p">这些应该留在 Bayesian-Agent 这一层。</p><p data-pid="0aXDlwcm">adapter 只负责一件事：</p><p data-pid="1B4rbLdD"><b>把 Bayesian-Agent 生成的 skill context 交给你的 agent，然后把运行轨迹带回来。</b></p><h2>四、依赖之前的轨迹，怎么接入？</h2><p data-pid="oPfDuPrp">如果你已经有一批历史运行结果，比如：</p><div class="highlight"><pre><code class="language-text"><span></span>baseline_results.json
</code></pre></div><p data-pid="AJAXDi0v">里面包含每个任务的 success/failure、token、输出、日志、failure mode 等信息，那可以先把这些历史轨迹喂给 Bayesian-Agent：</p><div class="highlight"><pre><code class="language-text"><span></span>bayesian-agent evolve \
  --results baseline_results.json \
  --registry temp/bayesian_skill_beliefs.json \
  --context-out temp/skill_context.md
</code></pre></div><p data-pid="4qZN_Oj-">这一步会做几件事：</p><ol>
<li data-pid="6nu9f63q">读取历史 trajectories；</li>
<li data-pid="WLyQ76tG">转成 <code>TrajectoryEvidence</code>；</li>
<li data-pid="WiuxYRfX">更新 Bayesian Skill Registry；</li>
<li data-pid="HIC02v8D">生成 posterior audit context 或下一轮 skill context。</li>
</ol><p data-pid="Fl-Nf_WR">然后可以找出 baseline 中失败的任务：</p><div class="highlight"><pre><code class="language-text"><span></span>bayesian-agent repair-plan \
  --baseline baseline_results.json \
  --out temp/failed_tasks.json
</code></pre></div><p data-pid="EmZKioOY">接下来有两种常见接法。</p><p data-pid="WQBYbC2y">第一种是 full self-evolution：</p><div class="highlight"><pre><code class="language-text"><span></span>从零开始跑所有任务
每跑一个 case 就更新一次 belief
下一条 case 使用更新后的 skill context
</code></pre></div><p data-pid="bjZZE0cd">第二种是 incremental repair：</p><div class="highlight"><pre><code class="language-text"><span></span>先读取已有 baseline trajectories
只挑失败 case 重跑
把修复结果和 baseline 合并
用更少 token 提升最终准确率
</code></pre></div><p data-pid="4Shc1BZ4">在真实业务里，我更推荐先从 incremental repair 开始。</p><p data-pid="SectDdbd">因为它最像一个即插即用模块：</p><div class="highlight"><pre><code class="language-text"><span></span>你的 agent 先跑一遍
Bayesian-Agent 分析失败轨迹
只重跑失败任务
把修复后的结果合并回去
</code></pre></div><p data-pid="qs0nGaWF">不用一上来就重构你的 agent 系统。</p><h2>五、我们已经有的 adapter</h2><p data-pid="XNrx33EO">目前仓库里已经有几个 adapter / backend：</p><h3>1. GenericAgent adapter</h3><p data-pid="HfQImvHG">GenericAgent 是我们最早验证 Bayesian-Agent 原型的地方。</p><p data-pid="5ySy2QVo">现在它已经不再被复制到 Bayesian-Agent 仓库里，而是作为一个 optional compatibility backend：</p><div class="highlight"><pre><code class="language-text"><span></span>python experiments/run_benchmarks.py \
  --harness genericagent \
  --genericagent-root /path/to/GenericAgent \
  --model deepseek-v4-flash \
  --bench core \
  --mode all
</code></pre></div><p data-pid="0Q08JVMF">这个 adapter 的边界很清楚：</p><ul>
<li data-pid="YxeGA5RV">GenericAgent 负责执行任务；</li>
<li data-pid="fT7QQ-rR">Bayesian-Agent 负责 benchmark orchestration、evidence collection、posterior update、skill evolution、incremental repair。</li>
</ul><p data-pid="bwaEO66Z">也就是说，我们没有 copy 一份 GenericAgent。</p><p data-pid="Tp84Hn3P">我们只是写了一个 adapter，让 GA 可以作为执行后端。</p><h3>2. mini-swe-agent adapter</h3><p data-pid="hWLPkE3_">mini-swe-agent 也可以作为 execution backend：</p><div class="highlight"><pre><code class="language-text"><span></span>python experiments/run_benchmarks.py \
  --harness mini-swe-agent \
  --mini-swe-agent-root /path/to/mini-swe-agent \
  --model deepseek-v4-flash \
  --bench realfin \
  --mode all
</code></pre></div><p data-pid="hu4RUUc1">它的定位也一样：</p><p data-pid="L2mPnwpu">mini-swe-agent 负责跑任务，Bayesian-Agent 负责把运行轨迹变成 skill evolution evidence。</p><p data-pid="fdtj4MEf">这种设计很重要。</p><p data-pid="1HJVbdco">因为同一个 Bayesian Skill Evolution Layer 可以挂在不同 agent harness 上，比较不同 backend 的执行能力，也可以观察 skill evolution 组件本身是否稳定有效。</p><h3>3. Claude Code adapter</h3><p data-pid="rfrjOalG">我们也加了 Claude Code CLI adapter：</p><div class="highlight"><pre><code class="language-text"><span></span>python experiments/run_benchmarks.py \
  --harness claude-code \
  --claude-cli claude \
  --model deepseek-v4-pro[1m] \
  --bench realfin \
  --mode all
</code></pre></div><p data-pid="ECTnfPb4">Claude Code 负责实际执行命令和生成结果。</p><p data-pid="zS_yCosP">Bayesian-Agent 负责：</p><ul>
<li data-pid="Px4a2ax9">接收它的 JSON / transcript；</li>
<li data-pid="jpqAaP9O">统计 token；</li>
<li data-pid="KAqB5XlP">交给 verifier；</li>
<li data-pid="a58E5uhX">更新 Skill Registry；</li>
<li data-pid="GvGwFUHK">为下一轮生成 Bayesian Failure-Mode Patches。</li>
</ul><p data-pid="mL--0G_v">这说明 Bayesian-Agent 的目标不是绑定某一个 agent 框架，而是做一个跨 harness 的 skill evolution layer。</p><h3>4. 一个直接的实验表格</h3><p data-pid="YBVoBdEU">为了避免这件事只停留在“接口设计很优雅”的层面，我们看几组已经跑完的代表性结果。</p><p data-pid="fiytb6w_">这里比较的不是“哪个 harness 天然更强”，而是更实际的问题：</p><p data-pid="rTEIFAt9"><b>在同一个 backend 内，把 Bayesian-Agent 接上去以后，是否能用历史轨迹和 Skill Evolution 继续提升结果？</b></p><table data-draft-node="block" data-draft-type="table" data-size="normal" data-row-style="normal"><tbody>

<li data-pid="gE41kT5k">很厚的 system prompt；</li>
<li data-pid="i-6PVaj_">多层 memory；</li>
<li data-pid="xgfLiI--">planner；</li>
<li data-pid="9nFV99hh">tool router；</li>
<li data-pid="ctzVj17T">reflection；</li>
<li data-pid="5ex9P6cd">retry；</li>
<li data-pid="dIJ8PY5F">long-horizon state；</li>
<li data-pid="2gtH3OoQ">framework-specific heuristics；</li>
<li data-pid="-Lh4tUGK">benchmark-specific hacks；</li>
</ul><p data-pid="R2xhRetQ">那么当结果变好时，我们很难回答：</p><p data-pid="Cw4BtK1e">到底是 Bayesian Skill Evolution 有用？</p><p data-pid="9SEMJnSR">还是 harness 本身某个隐含策略有用？</p><p data-pid="VSJct13z">这就是 native backend 的设计哲学：</p><p data-pid="x5JLYOHW"><b>让 harness 尽量小，把能力提升尽量推到 skill evolution layer。</b></p><p data-pid="ti9LwoNw">Bayesian-Agent native harness 只保留最小执行 substrate：</p><ul>
<li data-pid="dpjSF1gE">OpenAI-compatible LLM client；</li>
<li data-pid="Ke5Vap_u">workspace-scoped tools：<code>file_read</code>、<code>file_write</code>、<code>code_run</code>、<code>finish</code>；</li>
<li data-pid="08LJnKzi">turn loop；</li>
<li data-pid="g53hf9RE">tool dispatch；</li>
<li data-pid="SLeuFK6r">transcript capture；</li>
<li data-pid="OO4q98W3">token accounting；</li>
<li data-pid="oXkzBl0k">trajectory artifact。</li>
</ul><p data-pid="8kvBd3E3">native memory 默认关闭。</p><p data-pid="vWzJRDoI">如果你显式打开：</p><div class="highlight"><pre><code class="language-text"><span></span>--native-memory
</code></pre></div><p data-pid="IXQplHW5">它才会注入三层 memory context。</p><p data-pid="8xY8qrwa">默认关闭的原因也很简单：</p><p data-pid="yyoIIbFt">我们希望 baseline 和 Bayesian runs 的差异尽量来自 Skill Evolution Layer，而不是来自一个隐式增强的 memory system。</p><p data-pid="D5F8qzH0">换句话说，native backend 是为了让实验更干净。</p><p data-pid="nVuhC-D1">复杂 harness 更像生产系统。</p><p data-pid="8K9JlPh5">native backend 更像实验仪器。</p><h2>七、如何选择接入方式？</h2><p data-pid="AQsPSZDR">如果你只是想最快体验：</p><div class="highlight"><pre><code class="language-text"><span></span>python experiments/run_benchmarks.py \
  --harness bayesian-agent \
  --model deepseek-v4-flash \
  --bench core \
  --mode all \
  --limit 1
</code></pre></div><p data-pid="jAmt4SRo">如果你已经有自己的 agent：</p><div class="highlight"><pre><code class="language-text"><span></span>先写 adapter
再把历史 trajectories 转成 Bayesian-Agent 能读的 results
然后跑 incremental repair
</code></pre></div><p data-pid="-Y8k0SyE">如果你想验证某个新组件是否真的有用：</p><div class="highlight"><pre><code class="language-text"><span></span>优先用 native backend
保持 harness 简单
看新增组件对结果、token、failure mode 的影响
</code></pre></div><p data-pid="dF_kqwP6">如果你想在生产环境里用：</p><div class="highlight"><pre><code class="language-text"><span></span>保留自己的 agent / harness
让 Bayesian-Agent 做旁路 skill evolution
只把稳定 patch 注入下一轮任务
</code></pre></div><h2>八、Catalog skill 是必须的吗？</h2><p data-pid="EREdL0Gx">不是。</p><p data-pid="H9B4F1Zf">Bayesian-Agent 默认是 <code>use_skill_catalog=True</code>，也就是 catalog-first。</p><p data-pid="oPj43zvd">如果你已经有 benchmark-specific failure taxonomy 和 patch catalog，那它们就是很好的强先验，通常效果更好。</p><p data-pid="7VhJFvls">但如果你没有，也可以用：</p><div class="highlight"><pre><code class="language-text"><span></span>--no-use-skill-catalog
</code></pre></div><p data-pid="19fft_O7">这时 Bayesian-Agent 会进入 zero-shot automatic failure discovery：</p><div class="highlight"><pre><code class="language-text"><span></span>trajectory
  -&gt; verifier scores / errors / requested artifacts / output contract
  -&gt; auto failure mode
  -&gt; distilled repair rules
  -&gt; repeated evidence 后激活 patch
</code></pre></div><p data-pid="tAnGOJjU">我们最近做了一组对比：</p><p data-pid="n0I6fDWG">没有 catalog skills 时，BA 仍然能提升：</p><ul>
<li data-pid="ISNoe4vN">SOP-Bench incremental：70% -&gt; 100%</li>
<li data-pid="yYsVFCwd">RealFin-Bench full/incremental：38% -&gt; 45%</li>
</ul><p data-pid="qCqWV1is">有 catalog skills 时，BA 表现更强：</p><ul>
<li data-pid="NyJAgSsZ">SOP-Bench：最高 100%</li>
<li data-pid="-IKOLJNq">Lifelong AgentBench：最高 100%</li>
<li data-pid="tQU08avs">RealFin-Bench：最高 72%</li>
</ul><p data-pid="iebVubmM">这说明 catalog 不是 Bayesian-Agent 的全部。</p><p data-pid="lXK7_ZZb">catalog 更像强先验。</p><p data-pid="kQ2hWR2q">没有强先验时，Bayesian-Agent 仍然能通过轨迹证据发现重复失败，并形成 generic patches。</p><p data-pid="P-PvpUNR">有强先验时，它可以更快、更准、更稳。</p><h2>九、一个真实上手流程</h2><p data-pid="QHlZdH9X">如果你现在有一个自己的 agent，我建议按这个顺序接：</p><h3>Step 1：先保留你的 agent 不动</h3><p data-pid="Elh9HhvF">不要一开始就重构 harness。</p><p data-pid="cFyKCPGc">先确认你的 agent 能输出：</p><ul>
<li data-pid="RjTlAVFU">每个 task 的 id；</li>
<li data-pid="1G-vJ3sx">transcript；</li>
<li data-pid="qY6SV3DL">token usage；</li>
<li data-pid="TAvCz8YV">workspace / artifacts；</li>
<li data-pid="DMtyGGoX">verifier result；</li>
<li data-pid="dyovkkqL">error / failure reason。</li>
</ul><h3>Step 2：写一个薄 adapter</h3><p data-pid="VD2Jhnux">只实现：</p><div class="highlight"><pre><code class="language-text"><span></span>run(task, skill_context) -&gt; result
</code></pre></div><p data-pid="Rw62r8IT">把 <code>skill_context</code> 拼到 prompt 前面，调用你的 agent，然后返回 trajectory-like result。</p><h3>Step 3：把旧结果转成 evidence</h3><p data-pid="YVrOmCQ6">用历史 run：</p><div class="highlight"><pre><code class="language-text"><span></span>bayesian-agent evolve \
  --results old_results.json \
  --registry beliefs.json \
  --context-out skill_context.md
</code></pre></div><h3>Step 4：先跑 incremental repair</h3><p data-pid="LMU36WOf">不要急着全量重跑。</p><p data-pid="YFD8ZfGT">先找失败任务：</p><div class="highlight"><pre><code class="language-text"><span></span>bayesian-agent repair-plan \
  --baseline old_results.json \
  --out failed_tasks.json
</code></pre></div><p data-pid="N_6gns_g">然后只重跑失败任务。</p><p data-pid="4cWo0_Gc">这是最容易看到 ROI 的方式。</p><h3>Step 5：检查 artifacts，而不是只看 accuracy</h3><p data-pid="inatVJT8">Bayesian-Agent 会保存：</p><ul>
<li data-pid="ylczv6pT">belief json；</li>
<li data-pid="Tk0AygkJ">posterior audit context；</li>
<li data-pid="VHZk9Aka">skill context before/after；</li>
<li data-pid="EEldfX1Z">failure mode patches；</li>
<li data-pid="R3uo4laR">benchmark summary；</li>
<li data-pid="52YM7fUk">token / efficiency table。</li>
</ul><p data-pid="KXcbMKoA">我强烈建议不要只看最后 accuracy。</p><p data-pid="SkIqLc8B">要看它到底学到了什么：</p><div class="highlight"><pre><code class="language-text"><span></span>它识别了哪些 failure mode？
哪些 patch 被激活？
有没有过拟合？
token 是否下降？
失败是否集中在同一类问题？
</code></pre></div><p data-pid="33ZpsOdC">这才是 skill evolution 真正有价值的地方。</p><h2>十、总结</h2><p data-pid="4GIpn293">如果只用一句话概括 Bayesian-Agent 的上手方式：</p><p data-pid="qfLX6W_1"><b>不要把它当成替代你 agent 的新框架，而是把它当成一个可插拔的 Bayesian Skill Evolution Layer。</b></p><p data-pid="Ky_v391n">你可以：</p><ul>
<li data-pid="rqvQA7WB">保留自己的 agent；</li>
<li data-pid="wmKPBKxV">写一个薄 adapter；</li>
<li data-pid="GWFuprF-">复用已有 trajectories；</li>
<li data-pid="KFUZNTg8">用 Bayesian-Agent 更新 Skill belief；</li>
<li data-pid="bOc_6W7G">把生成的 Skill/SOP context 注入下一轮任务；</li>
<li data-pid="TnY8nzlf">先从 incremental repair 开始验证收益。</li>
</ul><p data-pid="dXIRWqc-">我们已经支持：</p><ul>
<li data-pid="0SE91qzg">Bayesian-Agent native backend；</li>
<li data-pid="iVj29yQV">GenericAgent adapter；</li>
<li data-pid="wuw7QzZ-">mini-swe-agent adapter；</li>
<li data-pid="MP8y7aM9">Claude Code adapter。</li>
</ul><p data-pid="Qpyb87xP">native backend 的价值是让实验干净、组件归因清楚。</p><p data-pid="bPu90sh4">external adapter 的价值是让 Bayesian Skill Evolution Layer 可以进入真实 agent 生态，而不是被锁死在某一个 harness 里。</p><p data-pid="ldk0SRcr">这也是我们一直强调的：</p><p data-pid="Toy9X81-">Bayesian-Agent 不是又一个孤立 agent framework。</p><p data-pid="6KOBomEu">它更像一层可以跨 harness 迁移的后天学习系统：</p><div class="highlight"><pre><code class="language-text"><span></span>experience -&gt; evidence -&gt; belief -&gt; skill rewrite -&gt; better next run
</code></pre></div><p data-pid="a7gEmzwG">这就是 Bayesian-Agent 快速上手的核心</p>
