if self.args.use_vllm:
    outputs = self.llm.generate(all_prompts_text, sampling_params=self.sampling_params, use_tqdm=False)
    completion_ids = [out.token_ids for completions in outputs for out in completions.outputs]
else:
    with unwrap_model_for_generation(self.model, self.accelerator) as unwrapped_model:
        prompt_completion_ids = unwrapped_model.generate(
            prompt_ids, attention_mask=prompt_mask, generation_config=self.generation_config
        )
</code></pre></div><p data-pid="OtXNzISu">这里，模型生成输出 <code>completion_ids</code> 的过程，实际上是从旧策略（当前模型）中采样一组输出。这些输出将被用于计算新策略的优化目标。</p><h3>2.2 计算奖励与优势函数</h3><p data-pid="Uoj2BmCi">接下来，代码中通过计算奖励和优势函数来优化策略模型。这部分对应了理论中的 <b>优势函数</b> 和 <b>奖励标准化</b>。</p><div class="highlight"><pre><code class="language-text"><span></span>rewards_per_func = torch.zeros(len(prompts), len(self.reward_funcs), device=device)
        for i, (reward_func, reward_processing_class) in enumerate(
            zip(self.reward_funcs, self.reward_processing_classes)
        ):
            if isinstance(reward_func, nn.Module):  # Module instead of PretrainedModel for compat with compiled models
                if is_conversational(inputs[0]):
                    messages = [{"messages": p + c} for p, c in zip(prompts, completions)]
                    texts = [apply_chat_template(x, reward_processing_class)["text"] for x in messages]
                else:
                    texts = [p + c for p, c in zip(prompts, completions)]
                reward_inputs = reward_processing_class(
                    texts, return_tensors="pt", padding=True, padding_side="right", add_special_tokens=False
                )
                reward_inputs = super()._prepare_inputs(reward_inputs)
                with torch.inference_mode():
                    rewards_per_func[:, i] = reward_func(**reward_inputs).logits[:, 0]  # Shape (B*G,)
            else:
                # Repeat all input columns (but "prompt" and "completion") to match the number of generations
                keys = [key for key in inputs[0] if key not in ["prompt", "completion"]]
                reward_kwargs = {key: [example[key] for example in inputs] for key in keys}
                output_reward_func = reward_func(prompts=prompts, completions=completions, **reward_kwargs)
                rewards_per_func[:, i] = torch.tensor(output_reward_func, dtype=torch.float32, device=device)
# Gather the reward per function: this part is crucial, because the rewards are normalized per group and the
# completions may be distributed across processes
rewards_per_func = gather(rewards_per_func)

# Sum the rewards from all reward functions
rewards = rewards_per_func.sum(dim=1)

# Compute grouped-wise rewards
mean_grouped_rewards = rewards.view(-1, self.num_generations).mean(dim=1)
std_grouped_rewards = rewards.view(-1, self.num_generations).std(dim=1)

# Normalize the rewards to compute the advantages
mean_grouped_rewards = mean_grouped_rewards.repeat_interleave(self.num_generations, dim=0)
std_grouped_rewards = std_grouped_rewards.repeat_interleave(self.num_generations, dim=0)
advantages = (rewards - mean_grouped_rewards) / (std_grouped_rewards + 1e-4)
</code></pre></div><p data-pid="WRhE56ec">这里，<code>rewards</code> 是模型生成的每个输出的奖励值，通过计算组内均值和标准差，将其标准化为 <code>advantages</code>。优势函数的作用是衡量某个输出相对于平均输出的优劣，从而引导模型优先提升高奖励输出的概率。</p><h3>2.3 KL散度</h3><p data-pid="WymDp-N7">在_prepare_inputs()中我们先获得ref模型每个token的概率分布 <code>ref_per_token_logps</code> </p><div class="highlight"><pre><code class="language-text"><span></span>with torch.inference_mode():
    if self.ref_model is not None:
        ref_per_token_logps = self._get_per_token_logps(
            self.ref_model, prompt_completion_ids, attention_mask, logits_to_keep
        )
    else:
        with self.accelerator.unwrap_model(self.model).disable_adapter():
            ref_per_token_logps = self._get_per_token_logps(
                self.model, prompt_completion_ids, attention_mask, logits_to_keep
            )
</code></pre></div><p data-pid="ptmevVHS"><code>ref_per_token_logps</code> 是参考策略（通常是 SFT 模型）的 log 概率值，用于衡量新策略与参考策略之间的差异。</p><p data-pid="KAZgWm10"><br>在 <code>compute_loss</code> 函数中，KL 散度的计算是通过以下代码实现的：</p><div class="highlight"><pre><code class="language-text"><span></span>per_token_kl = torch.exp(ref_per_token_logps - per_token_logps) - (ref_per_token_logps - per_token_logps) - 1
</code></pre></div><p data-pid="dlHhcgxf">这里，<code>ref_per_token_logps</code> 是参考策略（通常是 SFT 模型）的 log 概率值，而 <code>per_token_logps</code> 是新策略的 log 概率值。KL 散度的公式为：</p><p data-pid="ok-unXXq"><img eeimg="1" src="/assets/blog/images/e4946662e4651fe574e7.svg" alt="D_{KL}​(Pref​∣∣Pnew​)=\mathbb Ex∼P_{ref}​​[log{\frac{p_{\text{ref}}(x)}{p_{\text{new}}(x)}}​]"> </p><p data-pid="2AKC0xzG">在代码中，KL 散度通过以下近似公式计算：</p><p data-pid="yLH2ohOP"><img eeimg="1" src="/assets/blog/images/72a1d7b5cc7706a816b9.svg" alt="D_{KL}​(Pref​∣∣Pnew​)≈exp(logPref​−logPnew​)−(logPref​−logPnew​)−1"> </p><p data-pid="4boD8S1T">这种计算方式避免了直接计算对数概率的比值，提高了数值稳定性。</p><p data-pid="DbAjCXYT">要理解为什么代码中的公式是 KL 散度的近似计算方式，我们需要从 KL 散度的定义出发，并推导出其等价形式。</p><p data-pid="brh2xjlm">这里其实采用了泰勒展开的近似计算</p><p data-pid="yTsQr-cL">在语言模型中，通常使用对数概率（log probabilities）来表示分布，对数除法可以转换为减法因此DKL可以改写为：</p><p data-pid="XaD1Sdug"><img eeimg="1" src="/assets/blog/images/32495a3ee8eab8f2b2b6.svg" alt="D_{\text{KL}}(P_{\text{ref}} \| P_{\text{new}}) = \mathbb{E}_{x \sim P_{\text{ref}}} \left[ \log P_{\text{ref}}(x) - \log P_{\text{new}}(x) \right] "> </p><p data-pid="_AEi9h4a">我们可以通过泰勒展开的方式，将 KL 散度进一步简化为一个更稳定的近似公式。</p><p data-pid="nhE5jxK8">(1) 定义差值</p><p data-pid="_6Dpaczu">令 <img eeimg="1" src="/assets/blog/images/1e4a36aec41aabced4a6.svg" alt=" \Delta = \log P_{\text{ref}}(x) - \log P_{\text{new}}(x) "> ，即对数概率的差值。</p><p data-pid="r6hnSEji">KL 散度可以重写为：</p><p data-pid="Mm36kFzW"><img eeimg="1" src="/assets/blog/images/311b8dc38de648fa0b8f.svg" alt="D_{\text{KL}}(P_{\text{ref}} \| P_{\text{new}}) = \mathbb{E}_{x \sim P_{\text{ref}}} \left[ \Delta \right]"> </p><p data-pid="TueHBTeT">(2) 泰勒展开</p><p data-pid="SOasQ7Cc">为了提高数值稳定性，我们可以对指数函数 <img eeimg="1" src="/assets/blog/images/400667deecd6447f46fa.svg" alt="e^\Delta "> 进行泰勒展开。指数函数的泰勒展开为：</p><p data-pid="YBFRGCSM"><img eeimg="1" src="/assets/blog/images/faf176ec691f785d834f.svg" alt="e^\Delta \approx 1 + \Delta + \frac{\Delta^2}{2} + \cdots"> </p><p data-pid="aHDvWCa7">因此， <img eeimg="1" src="/assets/blog/images/f3cfb239d6bb85f01a02.svg" alt="e^\Delta - \Delta - 1"> 的近似形式为：</p><p data-pid="1ut_FLvB"><img eeimg="1" src="/assets/blog/images/49433de9ab55b31ae33c.svg" alt="e^\Delta - \Delta - 1 \approx \frac{\Delta^2}{2} + ··· "> </p><p data-pid="WkA8oJNb">当 \( \Delta \) 较小时，高阶项可以忽略，因此：</p><p data-pid="1MpgHn2V"><img eeimg="1" src="/assets/blog/images/2b6e5cf42b4385c2b9c1.svg" alt="e^\Delta - \Delta - 1 \approx \frac{\Delta^2}{2}"> </p><p data-pid="Q_s8ENwk"> (3) 替换回 KL 散度</p><p data-pid="WAredKwx">将 <img eeimg="1" src="/assets/blog/images/34a2f650d92c3b7bc969.svg" alt="\Delta = \log P_{\text{ref}}(x) - \log P_{\text{new}}(x) "> 代入，得到：</p><p data-pid="drPo8fqD"><img eeimg="1" src="/assets/blog/images/c745fa891e818d608507.svg" alt="D_{\text{KL}}(P_{\text{ref}} \| P_{\text{new}}) \approx \mathbb{E}_{x \sim P_{\text{ref}}} \left[ e^{\log P_{\text{ref}}(x) - \log P_{\text{new}}(x)} - (\log P_{\text{ref}}(x) - \log P_{\text{new}}(x)) - 1 \right]"></p><p data-pid="o2wejj_x">这正是compute_loss代码中实现的公式</p><h3>2.4 重要性采样</h3><p data-pid="Utv-aUPB">重要性采样是 GRPO 的核心机制之一，它通过复用旧策略的样本来估计新策略的优化方向。在代码中，重要性采样体现在 <code>per_token_logps</code> 计算中。</p><div class="highlight"><pre><code class="language-python3"><span></span><span class="n">per_token_logps</span> <span class="o">=</span> <span class="bp">self</span><span class="o">.</span><span class="n">_get_per_token_logps</span><span class="p">(</span><span class="n">model</span><span class="p">,</span> <span class="n">input_ids</span><span class="p">,</span> <span class="n">attention_mask</span><span class="p">,</span> <span class="n">logits_to_keep</span><span class="p">)</span>
</code></pre></div><p data-pid="Zy8zxJEw">这里，<code>per_token_logps</code> 是新策略的 log 概率值。重要性采样的核心思想是通过调整样本权重，用旧策略的样本来估计新策略的期望值。具体来说，重要性权重为：</p><p data-pid="R6EPAQm_"><img eeimg="1" src="/assets/blog/images/156e7f55e4daffb30148.svg" alt="\frac{p_{\text{new}}(x)}{p_{\text{old}}(x)}"> </p><p data-pid="rvqJXP88">在代码中，重要性采样权重通过以下方式体现：</p><div class="highlight"><pre><code class="language-text"><span></span>per_token_loss = torch.exp(per_token_logps - per_token_logps.detach()) * advantages.unsqueeze(1)
</code></pre></div><p data-pid="uIkP2xTR">这里，<code>torch.exp(per_token_logps - per_token_logps.detach())</code> 实际上就是重要性采样。</p><ul>
<li data-pid="U8wm1QwH">
<b>Log 概率的差值</b>：</li>
<ul>
<li data-pid="_FUDVewx">
<code>per_token_logps - per_token_logps.detach()</code> 计算的是新策略和旧策略的 log 概率差值，即： <img eeimg="1" src="/assets/blog/images/e3ca781dbeb516ccbada.svg" alt="\log \pi_{\theta}(o_i | q) - \log \pi_{\theta^{\text{old}}}(o_i | q)"> </li>
<li data-pid="cIW_XQgI">根据对数的性质，这个差值可以转化为概率的比值： <img eeimg="1" src="/assets/blog/images/548fad4d8859f1e03410.svg" alt="\log \pi_{\theta}(o_i | q) - \log \pi_{\theta^{\text{old}}}(o_i | q) = \log \left( \frac{\pi_{\theta}(o_i | q)}{\pi_{\theta^{\text{old}}}(o_i | q)} \right)"> </li>
</ul>
<li data-pid="KzTYhOJP">
<b>指数运算</b>：</li>
<ul><li data-pid="5NAx4iMf">通过 <code>torch.exp</code> 对 log 概率差值进行指数运算，可以得到概率的比值： <img eeimg="1" src="/assets/blog/images/214d0b492a4e2e9d37cd.svg" alt="\exp \left( \log \left( \frac{\pi_{\theta}(o_i | q)}{\pi_{\theta^{\text{old}}}(o_i | q)} \right) \right) = \frac{\pi_{\theta}(o_i | q)}{\pi_{\theta^{\text{old}}}(o_i | q)}"> </li></ul>
<li data-pid="hdImae0P">
<b>Detach 的作用</b>：</li>
<ul>
<li data-pid="yvTizBRw">
<code>per_token_logps.detach()</code> 的作用是将旧策略的 log 概率值从计算图中分离，避免在优化新策略时对旧策略的参数进行更新。</li>
<li data-pid="r6jiCHTP">这样可以确保重要性采样的权重仅用于调整样本的奖励，而不会影响旧策略的参数。</li>
</ul>
</ul><p data-pid="iNpmFYga">而<code>*advantages.unsqueeze(1)</code> 就是优势函数啦，用于衡量某个输出相对于平均输出的优劣。通过重要性权重调整优势函数，模型可以优先提升高奖励输出的概率，从而实现策略优化。</p><h3>2.5 最终loss</h3><p data-pid="V6pua6cN">最后再回顾第一篇所说的那样，损失函数的构建结合了优势函数和 KL 散度：</p><figure data-size="normal"><img src="/assets/blog/images/234d99f44e2a40573169.png" data-caption="" data-size="normal" data-rawwidth="1440" data-rawheight="796" class="origin_image zh-lightbox-thumb" width="1440" data-original="/assets/blog/images/234d99f44e2a40573169.png"></figure><div class="highlight"><pre><code class="language-text"><span></span>per_token_loss = torch.exp(per_token_logps - per_token_logps.detach()) * advantages.unsqueeze(1)
per_token_loss = -(per_token_loss - self.beta * per_token_kl)
loss = ((per_token_loss * completion_mask).sum(dim=1) / completion_mask.sum(dim=1)).mean()
</code></pre></div><p data-pid="5TA44zR-">这里，<code>per_token_loss</code> 由两部分组成：</p><ol>
<li data-pid="a4vZ6xz1">
<b>优势函数部分</b>：<code>torch.exp(per_token_logps - per_token_logps.detach()) * advantages.unsqueeze(1)</code>，这部分通过优势函数引导模型优先提升高奖励输出的概率。</li>
<li data-pid="r9-hwerq">
<b>KL散度部分</b>：<code>self.beta * per_token_kl</code>，这部分通过 KL 散度限制新策略与参考策略之间的差异，self.beta就是公式中那个 <img eeimg="1" src="/assets/blog/images/f3f83d8421853f8ef943.svg" alt="\beta"> 啦。</li>
<li data-pid="a0jApz0l">(per_token_loss - self.beta * per_token_kl)就是第一篇要<b>最大化的那个 </b><img eeimg="1" src="/assets/blog/images/2809f50148acf3d9fe24.svg" alt="\mathcal{J}_{GRPO}(\theta) "><b> 啦</b>，再加个负号-(per_token_loss - self.beta * per_token_kl)不就是我们要<b>最小化的loss了嘛666。</b>最终，损失函数是每个token的loss的加和然后平均。其中，completion_mask 用于忽略填充部分的损失。</li>
<li data-pid="RUen2prb">clip那部分在huggingface这版实现中还没找到，也可能是没实现，因为就像第一篇所说，这一部分其实不是必须的。</li>
</ol><p><br></p><p data-pid="bNorWQ12"><br><br>最后我们发个预告：第三篇——适配自定义任务</p><p data-pid="_rV82SU7">在第三篇中，我们将探讨如何利用 Open-R1 框架适配自定义任务。以 <b>金融股价预测</b> 为例，我们将构建一个 <b>Finance-R1</b> 模型，通过强化学习提升 LLM 在股价预测上的深度推理能力和预测准确性。具体内容包括：</p><ol>
