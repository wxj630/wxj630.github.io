</blockquote><p data-pid="p7ToJNfu"><b>让一个经典思想在LLM Agent的新时代延续荣光、发光发热!</b></p><p data-pid="BAQZjgtP">系列文章更新中。。。</p><blockquote data-pid="EKJJ8NTt"><a href="https://zhuanlan.zhihu.com/p/2036275199008565089" class="internal" target="_blank">Bayesian Agent （一）：让 Harness 与 Skills 的 Self-Evolving过程不再黑盒、没有方向，走向贝叶斯信念</a></blockquote><p data-pid="uH5WaRnZ">过去一年，Agent 框架越来越多。每个框架都在讲工具调用、memory、planner、browser、workflow、multi-agent，但如果把这些概念拨开，本质问题其实很朴素：</p><p data-pid="Ws1byklm"><b>一个 Agent 做错了一次任务之后，它到底有没有真的变聪明？</b></p><p data-pid="8Rem_VN-">很多系统的答案并不令人满意。失败轨迹可能被塞进长上下文，成功经验可能被写成一段 prompt，SOP 可能越积越厚，但这些“经验”通常没有明确的证据权重，也很少回答三个问题：</p><ol>
<li data-pid="MvaZdn3V">这条 Skill 到底在什么场景下有效？</li>
<li data-pid="Xsj9rMaK">它失败时通常死在哪个 failure mode？</li>
<li data-pid="xNgnOrK2">继续使用它，是省 token，还是在制造噪声？</li>
</ol><p data-pid="WLkzP9Uq">这就是我们开源 <b>Bayesian-Agent: A Bayesian Self-Evolving Agent Framework with Cross-Harness Adaptation</b> 的原因。</p><p data-pid="kUVM6XhW">Bayesian-Agent 不是又一个试图替代所有人的 Agent runtime。它更像一个可以挂在不同 Agent harness 旁边的 <b>Bayesian Skill/SOP evolution layer</b>：从 Agent 的成功和失败轨迹中提取证据，维护每条 Skill 的 posterior belief，再把更可靠、更省 token、更贴近当前任务的 Skill context 注入下一次运行。</p><h2>一、一句话介绍</h2><p data-pid="OkAjY6oS">Bayesian-Agent 把 Agent 的每条 Skill / SOP 当成一个关于成功率的假设：</p><div class="highlight"><pre><code class="language-text"><span></span>P(success | theta, C, skill)
</code></pre></div><p data-pid="uhAYC0Yj">其中：</p><ul>
<li data-pid="hJNvdUss">
<code>theta</code> 是底层大模型参数</li>
<li data-pid="yvkQzLvY">
<code>C</code> 是推理环境，包括 prompt、context、tools、memory、harness feedback</li>
<li data-pid="HaE_si5b">
<code>skill</code> 是可复用的任务流程或 SOP</li>
</ul><p data-pid="nxWdgonZ">每次 Agent 执行任务后，Bayesian-Agent 会读取经过验证的 trajectory evidence，更新 Skill 的 posterior belief，并在下一次运行时生成 posterior-weighted Skill context。</p><p data-pid="siIz0jAO">换句话说，它不是“把失败经历都塞进记忆里”，而是问：</p><p data-pid="PHx7uwA-"><b>哪些经验被验证过？哪些经验在当前任务里值得相信？哪些经验应该 patch、split、compress 或 retire？</b></p><h3>仓库架构图</h3><p data-pid="UFc-_oqV">下面这张图是当前仓库结构和数据流。核心点是：Bayesian-Agent 的 <code>core</code> 不绑定任何具体 Agent runtime；GenericAgent 只是当前实验使用的 backend harness，未来也会上传我们自己的 Agent harness。</p><figure data-size="normal"><img src="/assets/blog/images/8eb69e0f2969fec09b49.png" data-caption="" data-size="normal" data-rawwidth="4500" data-rawheight="2875" class="origin_image zh-lightbox-thumb" width="4500" data-original="/assets/blog/images/8eb69e0f2969fec09b49.png"></figure><p data-pid="O63M6JOS"><br> <i>Bayesian-Agent repository architecture: a reusable Bayesian Skill/SOP evolution layer across harnesses.</i> </p><p data-pid="BQhR7O_Z">仓库中最重要的几层是：</p><ul>
<li data-pid="X3GdYGc_">
<code>bayesian_agent/core/</code>：框架无关的 Bayesian evolution engine</li>
<li data-pid="GOQY9kDO">
<code>bayesian_agent/adapters/</code>：外部 Agent harness 的适配边界</li>
<li data-pid="TUGuZJzX">
<code>schemas/</code>：trajectory evidence 和 Skill belief 的通用 JSON schema</li>
<li data-pid="740LC4n8">
<code>artifacts/</code>：GenericAgent + deepseek-v4-flash 的实验结果</li>
<li data-pid="_ag9g6Mo">
<code>docs/</code>：方法、实验、API、adapter 和部署文档</li>
</ul><p data-pid="0GZcSc22">这个边界设计很重要。它意味着 Bayesian-Agent 不需要复制 GenericAgent，也不需要把自己变成一个封闭的大型 Agent 框架。只要某个 Agent framework 能产出统一的 trajectory schema，它就可以接入 Bayesian-Agent。</p><p data-pid="Q6eHuQ4H">如果基础模型是在采样：</p><div class="highlight"><pre><code class="language-text"><span></span>P(X | theta)
</code></pre></div><p data-pid="5A0g86vp">那么 Agent 系统其实是在采样：</p><div class="highlight"><pre><code class="language-text"><span></span>P(X | theta, C)
</code></pre></div><p data-pid="uXuqpSMe">这里的 <code>C</code> 就是整个推理环境。所谓 prompt engineering、context engineering、RAG、tool use、memory、harness engineering，本质上都在改变 <code>C</code>，从而改变模型下一步吐字和行动的条件概率分布。</p><p data-pid="rJiKPBh0">Bayesian-Agent 聚焦的是 Skill / SOP 这一层 <code>C</code> 的进化。</p><p data-pid="eSjVX1LV">传统做法像是：</p><div class="highlight"><pre><code class="language-text"><span></span>做过一次 -&gt; 写进经验 -&gt; 下次看到类似任务就用
</code></pre></div><p data-pid="g-0YiFEC">Bayesian-Agent 的做法是：</p><div class="highlight"><pre><code class="language-text"><span></span>执行轨迹 -&gt; Verifier -&gt; Evidence -&gt; Posterior -&gt; Skill Context -&gt; 下一次执行
</code></pre></div><p data-pid="_vKM6rwK">这让 Skill 不再是“看起来有用的一段提示词”，而是一个被持续验证、持续修正、持续压缩的操作假设。</p><h2>二、三个核心优势</h2><h3>1. 从零跑：Full Self-Evolving Mode</h3><p data-pid="ynnl53RL">Bayesian-Agent 可以从零开始运行任务。没有历史 traces，没有人工预置的大量 SOP，也可以在任务执行过程中收集 evidence，并逐步进化 Skill beliefs。</p><p data-pid="1xmln8uR">这对应的是研究问题：</p><p data-pid="SwCpM-TH"><b>一个 Agent 能不能在没有先验经验的情况下，通过执行和验证自我沉淀 Skill？</b></p><p data-pid="BEFnkzoF">在 SOP-Bench 上，我们用 GenericAgent + <code>deepseek-v4-flash</code> 做了原型验证：</p><table data-draft-node="block" data-draft-type="table" data-size="normal" data-row-style="normal"><tbody>

</code></pre></div><p data-pid="qIyHhUui">也就是：</p><ol>
<li data-pid="JlB4IM4k">原来的 Agent 先跑</li>
<li data-pid="FiMz_o8b">Bayesian-Agent 读取成功和失败轨迹</li>
<li data-pid="GP306OZ4">对失败模式进行 posterior update 和 repair planning</li>
<li data-pid="Sde2ks3w">只重跑失败任务</li>

<li data-pid="3RYZkI2V">外部 Agent 需要产出 <code>TrajectoryEvidence</code>
</li>
<li data-pid="Lf1Mq33U">外部 Agent 能接收 posterior-weighted Skill context</li>
</ul><p data-pid="icf3-nRX">最小 adapter contract 是：</p><div class="highlight"><pre><code class="language-text"><span></span>class AgentAdapter(Protocol):
    def run(self, task: Mapping[str, Any], skill_context: str) -&gt; Mapping[str, Any]:
        ...
</code></pre></div><p data-pid="_ObqpSUF">这意味着 GenericAgent、我们后续上传的自研 Agent harness，以及其他 agent frameworks，都可以作为 Bayesian-Agent 的 backend。</p><p data-pid="PRgWy6Ce">我们希望 Bayesian-Agent 成为一个 <b>Skill evolution substrate</b>，而不是又一个孤立的 Agent 应用。</p><h2>三、安装与使用</h2><p data-pid="Kz6da-0u">安装方式：</p><div class="highlight"><pre><code class="language-text"><span></span>git clone https://github.com/DataArcTech/Bayesian-Agent.git
cd Bayesian-Agent
python -m pip install -e .
</code></pre></div><p data-pid="eDrbQgm_">CLI 示例：</p><div class="highlight"><pre><code class="language-text"><span></span>bayesian-agent evolve \
  --results artifacts/ga_deepseek_baseline/sop_results.json \
  --registry temp/bayesian_skill_beliefs.json \
  --context-out temp/skill_context.md
</code></pre></div><p data-pid="_wjzwhW5">Python API 示例：</p><div class="highlight"><pre><code class="language-text"><span></span>from bayesian_agent import BayesianSkillRegistry, SkillContextBuilder, TrajectoryEvidence

registry = BayesianSkillRegistry("temp/beliefs.json")
registry.record(
    TrajectoryEvidence(
        task_id="sop_12",
        skill_id="benchmark/sop_bench",
        context="sop_bench",
        outcome="failure",
        failure_mode="xml_wrapped_answer",
        input_tokens=70123,
        output_tokens=4242,
    )
)

print(SkillContextBuilder(registry).render(task_context="sop_bench"))
</code></pre></div><h3>和普通 Agent 框架的区别</h3><p data-pid="EQjpisp-">我觉得可以用一句话概括：</p><p data-pid="IuHQGh-y"><b>普通 Agent 框架关注“怎么执行任务”，Bayesian-Agent 关注“执行经验如何被验证、加权、修复、迁移”。</b></p><p data-pid="01PVS762">所以它不是在和 GenericAgent、OpenHands、Claude Code、各类 browser agent 抢同一个位置。</p><p data-pid="qUG3RO0V">更准确的位置是：</p><div class="highlight"><pre><code class="language-text"><span></span>Agent Harness below
Bayesian Skill Evolution above
</code></pre></div><p data-pid="7x4wezUC">底层 harness 负责执行任务，Bayesian-Agent 负责从执行轨迹中学习，形成可迁移的 Skill posterior。</p><p data-pid="VNlzmgrI">这也是为什么我们强调 cross-harness adaptation。因为未来真正有价值的 Agent 资产，可能不是某一个 runtime，而是跨 runtime 可复用的 verified operational knowledge。</p><h3>Roadmap</h3><p data-pid="GEZ_wD40">接下来我们会继续做几件事：</p><ul>
<li data-pid="jpwSTEV5">上传我们自己的 Bayesian-Agent harness，让用户不依赖 GenericAgent 也能完整跑 full loop</li>
<li data-pid="zMFhDU1o">完善更多 agent frameworks 的 adapter examples</li>
<li data-pid="zm4-TMqE">增加更丰富的 rewrite policy，比如 context-specific split、cost-aware compression、failure taxonomy</li>
<li data-pid="EE9fBohR">加入可执行 benchmark runner，方便外部复现实验</li>
<li data-pid="hDtYR1LQ">推进论文版本，arXiv coming soon</li>
</ul><h3>结语</h3><p data-pid="LhEPEo93">Agent 的下一阶段，不只是更强的工具调用，也不只是更长的上下文。</p><p data-pid="0L3EGjmA">更关键的问题是：</p><p data-pid="Rgc33lLg"><b>Agent 的经验如何成为可验证、可更新、可迁移的工程资产？</b></p><p data-pid="EvMG8j0X">Bayesian-Agent 给出的答案是：把 Skill/SOP 当成假设，把执行轨迹当成证据，用 Bayesian posterior 管理它们的可靠性和成本。</p><p data-pid="h2Pq-YGg">如果说 prompt engineering 解决的是“怎么问”，context engineering 解决的是“给模型看什么”，harness engineering 解决的是“怎么让模型做事”，那么 Bayesian-Agent 想解决的是：</p><p data-pid="9yuMCRIY"><b>做完之后，系统如何真正进化。</b></p><p data-pid="YjYUINQG">仓库地址：<br><a href="http://link.zhihu.com/?target=https%3A//github.com/DataArcTech/Bayesian-Agent" class=" external" target="_blank" rel="nofollow noreferrer"><span class="invisible">https://</span><span class="visible">github.com/DataArcTech/</span><span class="invisible">Bayesian-Agent</span><span class="ellipsis"></span></a></p><p data-pid="KuyhPJzy">文档地址：<br><a href="http://link.zhihu.com/?target=https%3A//dataarctech.github.io/Bayesian-Agent/" class=" wrap external" target="_blank" rel="nofollow noreferrer">Bayesian-Agent: A Bayesian Self-Evolving Agent Framework with Cross-Harness Adaptation</a></p>
