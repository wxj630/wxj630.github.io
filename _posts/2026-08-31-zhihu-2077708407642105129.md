</ul><p data-pid="VB2Xc0W1">当然，这里的评测主要是数学建模和计算代码求解领域；这份榜单主要用于自己测试和观察各大模型的性价比，方便后续挑选使用，不能代表各家模型的综合能力。若还有其他模型想一起测，也欢迎私信补充测评对象。</p><p data-pid="DVqr5_4F">每个任务我们给足4个小时的agent执行时间。</p><h2>一、省流版</h2><p data-pid="XqN-88Fy">如果只看 TB-MathModel 这 18 道题，三家 Flash 的结论其实很清楚：</p><ol>
<li data-pid="nqxYJLJI">
<b>DeepSeek-v4-Flash-0731 最稳</b>，O-Eval 最高，成本也最低。</li>
<li data-pid="xQnt6c0-">
<b>GLM-5.3-Flash 最会追分</b>，Robust BO-Eval 最高，说明它在 baseline 弱项上追回得更猛。</li>
<li data-pid="gKYaHrIL">
<b>Qwen3.8-Flash（百炼）这轮最吃亏</b>，总分最低，成本最高，而且还有两个最终超时失败。</li>
</ol><p data-pid="XEQW7Ua_">一句话说完就是：</p><p data-pid="hchopeyf"><b>如果只选一个主力，先选 DeepSeek-v4-Flash；如果更想看谁会在弱项上狠狠干一把，GLM-5.3-Flash 更有故事；Qwen3.8-Flash 这轮不太适合当主力。</b></p><p data-pid="pPCbfjey"><b>我觉得可能某种意义上Qwen3.8-Flash总参数量最少、激活参数量也最少可能拖累了他的性能：</b></p><ul>
<li data-pid="ZOCLoyRG">DeepSeek-V4-Flash：284B 总参数，13B 激活参数。(<a href="https://link.zhihu.com/?target=https%3A//huggingface.co/deepseek-ai/DeepSeek-V4-Flash" data-draft-type="text-link" data-icon-name="zhicon_icon_24_link" class=" wrap external" target="_blank" rel="nofollow noreferrer">​huggingface.co</a>)</li>
<li data-pid="eu43pNB3">GLM-5.3-Flash：320B 总参数，18B 激活参数。(<a href="https://link.zhihu.com/?target=https%3A//docs.z.ai/guides/vlm/glm-5.3-flash" data-draft-type="text-link" data-icon-name="zhicon_icon_24_link" class=" wrap external" target="_blank" rel="nofollow noreferrer">​docs.z.ai</a>)</li>
<li data-pid="NTLDwupC">Qwen3.8-Flash-Next：125B 主模型参数，外加 51B n-gram embedding；每 token 激活 6B。如果把 embedding 也算进总量，可以记成约 176B / 6B。(<a href="https://link.zhihu.com/?target=https%3A//huggingface.co/Qwen/Qwen3.8-Flash-Next" data-draft-type="text-link" data-icon-name="zhicon_icon_24_link" class=" wrap external" target="_blank" rel="nofollow noreferrer">​huggingface.co</a>)</li>
</ul><h3>我们到底怎么比</h3><p data-pid="cKP23B-f">TB-MathModel 不是在比谁会写一篇看起来最像论文的报告，而是在比：给完整赛题、附件、终端环境之后，模型最后能不能把关键数值真的做出来。</p><p data-pid="UXvCCXDg">所以我们用了两把尺子：</p><div class="highlight"><pre><code class="language-text">O-Eval = direction-aware raw / O raw</code></pre></div><p data-pid="SoVb-mJo">它看的是绝对能力，回答的是“离优秀论文复现答案有多近”。</p><p data-pid="bSigTvZc">Robust BO-Eval 则看相对 v4 flash baseline 的稳健增益：</p><ul>
<li data-pid="YepuZXSl">
<code>O raw - flash raw &gt;= 0.10</code> 时，用追回比例，但截到 <code>[-100%, +100%]</code>
</li>
<li data-pid="mWham7df">分母太小的时候，不再硬算比例，改成 clipped B-Eval，也就是把 <code>model raw - flash raw</code> 截到 <code>[-10pp, +10pp]</code>
</li>
<li data-pid="DPCRcDYb">trial 最后没有产出可评分结果时，直接记 <code>-100%</code>
</li>
</ul><p data-pid="KOuZPqfU">所以这两个指标本来就不是一回事：</p><ul>
<li data-pid="ePfC-fPR">
<b>O-Eval</b> 看的是绝对分</li>
<li data-pid="NsIsKF-e">
<b>Robust BO-Eval</b> 看的是相对追赶</li>
</ul><p data-pid="jiYNnW5d">v4 flash 在这里是基线，不参与追赶，所以它的 Robust 值天然是 0。</p><h3>三家 Flash 的成绩单</h3><table data-draft-node="block" data-draft-type="table" data-size="normal" data-row-style="normal"><tbody>

</ul><h2>二、三个Flash模型主要表现</h2><h3>1. DeepSeek-v4-Flash-0731</h3><p data-pid="qPMWcTS3">这轮里它是最像“默认主力”的那个。</p><p data-pid="KyvDpdW-">它的 O-Eval 最高，说明它和优秀论文复现答案的贴合度最好；同时它的成本也是最低的。对于 agent 场景来说，这一点很关键，因为真正烧钱的不是一次回答，而是读题、写代码、跑求解器、调参、重试、补结果的一整串动作。</p><p data-pid="9YiAYsTI">能在最便宜的前提下把绝对分做到最高，这个模型就很适合做首选基线。</p><h3>2. GLM-5.3-Flash</h3><p data-pid="U9gR-NYa">GLM-5.3-Flash 的故事更像“追分型选手”。</p><p data-pid="YTSyzdWM">它的 O-Eval 比 DeepSeek-v4-Flash 低一点，但 Robust BO-Eval 反而更高，说明它在一些 baseline 弱项上追得更猛。换句话说，它不是最贴近 O 的那个，但它更擅长在某些题上把 flash baseline 甩开。</p><p data-pid="2mRkANJw">这就是为什么它在 Robust 图里会显得特别亮眼。</p><p data-pid="FFconpRh">如果关心的是“相对便宜 baseline 到底能不能被狠狠干掉”，GLM-5.3-Flash 很值得看； 但如果关心的是“谁最接近 O 奖答案”，它就不是第一。</p><h3>3. Qwen3.8-Flash（百炼）</h3><p data-pid="oDGQDnus">Qwen3.8-Flash 这轮最大的问题不是“没跑完”，而是“跑完了也不够稳”。</p><p data-pid="81tf7m6u">它确实覆盖了 18 题，但只有 16 个有效完成，另外 2 个是最终超时失败。更关键的是，它在 MCM 上明显弱一些，Robust 还是负的。</p><p data-pid="2J8R5iCq">再加上它的 token footprint 很大，输入、缓存、输出三项都重，所以最后就会显得特别贵。</p><p data-pid="R45EH3ES">所以这轮给人的直观感受就是：</p><p data-pid="G5gRNYVA"><b>花得最多，分却不是最漂亮。</b></p><h3>为什么 O-Eval 和 Robust 会“看起来打架”</h3><p data-pid="YMqaPrjE">它们本来就是两把不同的尺子。</p><p data-pid="xX30WeMZ">O-Eval 问的是：你离优秀论文复现答案有多近？</p><p data-pid="aPwREFgL">Robust BO-Eval 问的是：你比便宜 baseline 多追回了多少？</p><p data-pid="gHMSvfyX">所以很自然会出现这种情况：</p><ul>
<li data-pid="_xe-_KJN">有些模型绝对分更高，但相对追赶没那么猛</li>
<li data-pid="dM-Fh5nX">有些模型在 baseline 弱项上追得很凶，但绝对贴合度还是不如另一个模型</li>
</ul><p data-pid="p0S7tHQn">这不是矛盾，是互补。</p><p data-pid="HZ8qtWwP">论文主榜应以 O-Eval 为主； 分析图则更适合保留 Robust，用来解释“为什么某些模型在某些题上特别会追分”。</p><h3>最后怎么选</h3><p data-pid="Jh7F3q6k">如果只给一句最实用的建议：</p><ul>
<li data-pid="SOxidYra">
<b>默认主力</b>：DeepSeek-v4-Flash-0731</li>
<li data-pid="M8NT7Y4y">
<b>看相对追分能力</b>：GLM-5.3-Flash</li>
<li data-pid="xuThq-7M">
<b>这轮不建议作为主力</b>：Qwen3.8-Flash（百炼）</li>
</ul><p data-pid="7L5QxqJM">下一篇将把这三家在 18 题里的具体题目、轨迹和可行解拆开讲，看看它们到底是在哪些题上赢、在哪些题上翻车。</p><p data-pid="Q05tPJsH">不过这件事也不用等下一篇了，既然大家最关心的是“到底哪几题赢、哪几题翻车”，我们就直接在这篇拆完。</p><h2>三、结果可视化</h2><p <li data-pid="g7k18jTz">
<b>有没有 artifact</b>：有没有最后写出 <code>/root/results/*_result.json</code> 这种可评分结果。</li>
<li data-pid="2-h10235">
<b>有没有关键数值</b>：结果 JSON 里的字段是否能被评测器读到，单位和方向是否合理。</li>
<li data-pid="_0yf62QN">
<b>轨迹是否像真的求解</b>：trajectory 里是不是有读题、读附件、写 Python、调用数值库/优化库、跑出中间结果、再汇总结果的过程。</li>
</ol><p data-pid="Nt-jRGuB">注意，这里的“可行解”不是说它一定已经达到人类论文的所有严谨性。它更准确的意思是：</p><p data-pid="tnKam-tn"><b>在统一环境里，模型给出了能被程序化 verifier 检查的关键数值答案。</b></p><p data-pid="hjS7Ao5_">这比纯文本报告评分强很多，因为它至少逼模型真的跑代码、真的交结构化结果；但它也不是万能的。比如某些题的 O-Eval 超过 100%，可能是模型在某些指标上比 O 奖复现答案更激进，也可能是评测指标没有覆盖所有隐含约束。所以看到 145%、255% 这种分数时，不能简单理解成“模型真实世界里吊打人类”，而应该理解成：</p><p data-pid="Uz0qhxCS"><b>在当前可验证指标上，它交出了比 O 锚点更优的若干关键数值。</b></p><p data-pid="P13HPCW3">这也是我们为什么要引入 Robust BO-Eval：小分母、过度优化、局部超分都不能让它无限爆炸，赢很多和输很多都一起截断。</p><h2>四、Qwen3.8-27B-FP8 thinking：和三家 Flash 放一起看</h2><p data-pid="pduVixmi">如果把 Qwen3.8-27B-FP8 thinking 和这三家 Flash 摆在同一张桌上，它的位置其实非常清楚：</p><p data-pid="rpmeTolP"><b>它是这组结果里绝对分最高的那个，但也是最贵的那个。</b><br><b>这是因为他是一个Dense模型，其实是激活参数量反而比3个Flash模型多，但是他的优势是总参数量小，本地部署比较方便。对比下：</b></p><ul>
