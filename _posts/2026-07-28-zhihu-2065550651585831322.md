<p data-pid="1qjnj_Kv">前几篇我们一直在做一类事：</p><p data-pid="qc5QtANa"><b>已知方程、已知初值、已知参数，往前算曲线。</b></p><p data-pid="a8PQ7lUC">这一篇换个方向。</p><p data-pid="wWKYFBjN"><b>如果题目只给你观测数据，不告诉你 <code>beta</code>、<code>gamma</code> 这些参数，你怎么把它们反推出来？</b></p><p data-pid="FWKyz8Z2">先给一句人话答案：</p><p data-pid="LSCUMxhp"><b>先用微分方程生成一条“猜的曲线”，再拿它和真实数据比差距，差距越小，参数越像真的。</b></p><p data-pid="l7SMlHD1">这就是参数识别，也可以理解成“把数据拟合回方程里”。</p><p data-pid="RzPRnq8m">这一节的 takeaway：<b>微分方程不只会正向求解，还可以反过来做参数标定。</b></p><h3>0. 先看最小问题</h3><p data-pid="gGrroge5">还是用第二篇的 <code>SIR</code> 模型。</p><p data-pid="kYh-MkC9"><code>SIR</code> 是 <code>Susceptible-Infectious-Recovered</code> 的缩写，中文通常叫“易感者-感染者-康复者模型”。</p><p data-pid="KmxZgYAZ">这一次我们不再问“曲线会怎么走”，而是问：</p><p data-pid="LbqGmwy0"><b>如果我已经看到了几天的感染人数，能不能倒推出这次传播有多强、恢复有多快？</b></p><p data-pid="RA9H90Nn">这类问题很常见：</p><ul>
<li data-pid="dyuAP1FL">疫情数据反推传播参数</li>
<li data-pid="i_wMnT_3">药物浓度反推代谢速率</li>
<li data-pid="TfMiMeip">生态数据反推种群增长率</li>
</ul><p data-pid="Bgef0meL">这一节的 takeaway：<b>很多建模题不是在算未来，而是在用数据倒推模型里的参数。</b></p><figure data-size="normal"><img src="/assets/blog/images/4fb7a2b5211180e68287.png" data-caption="" data-size="normal" data-rawwidth="3520" data-rawheight="1980" class="origin_image zh-lightbox-thumb" width="3520" data-original="/assets/blog/images/4fb7a2b5211180e68287.png" data-original-token="v2-f49d3200224366605d23da85ba85354d"></figure><p class="ztext-empty-paragraph"><br></p><h3>1. 变量和未知量不是一回事</h3><p data-pid="6k49e1W6">这一篇里有两层量。</p><p data-pid="ExdaDXmH">第一层是状态变量：</p><ul>
<li data-pid="DXna6Ela">
<code>S(t)</code>：易感者比例</li>
<li data-pid="usWIGy2h">
<code>I(t)</code>：感染者比例</li>
<li data-pid="Tf-PdRoh">
<code>R(t)</code>：康复者比例</li>
</ul><p data-pid="2auyd2Uc">第二层是参数：</p><ul>
<li data-pid="9LTPjRCC">
<code>beta</code>：传播速率</li>
<li data-pid="5SCEPFcT">
<code>gamma</code>：康复速率</li>
</ul><p data-pid="zjHMcZu3">状态变量是“这一天系统长什么样”。<br>参数是“这套系统的性格有多强”。</p><p data-pid="fq9qXr1z">这里最容易犯的错，是把参数当成状态。</p><p data-pid="o_d7NSZ7">例如 <code>beta</code> 和 <code>gamma</code> 不是每天都在变的曲线，它们更像是模型的旋钮。<br>如果你换一批数据，旋钮可能要重拧，但在一次拟合里，它们通常先假设为常数。</p><p data-pid="0yxoDNZ7">顺手再提醒一句：</p><p data-pid="Dsx48Diz"><code>beta</code> 和 <code>gamma</code> 不是概率，不需要卡在 <code>0</code> 到 <code>1</code> 之间，也不一定要“大于 1”。<br>它们是按时间单位计的速率，常见写法就是“每天 0.32 次”“每天 0.10 次”。</p><p data-pid="OOcEy41_">这一节的 takeaway：<b>状态变量描述系统当前状态，参数描述系统运行方式。</b></p><h3>2. 先造一份能验算的假数据</h3><p data-pid="F3Dj_UZv">最小可用做法不是直接上真实数据，而是先造一份“像真的”数据。</p><p data-pid="2L3R6gxr">这样有两个好处：</p><ol>
<li data-pid="_h7-M0zB">你知道真相，方便检查拟合有没有跑偏</li>
<li data-pid="uuHCbQnp">你可以控制噪声大小，观察拟合有多稳</li>
</ol><p data-pid="cAe9xXJe">我们先选一组“真参数”：</p><ul>
<li data-pid="UlYzp8-F"><code>beta_true = 0.32</code></li>
<li data-pid="OjGPHhzW"><code>gamma_true = 0.10</code></li>
</ul><p data-pid="81ouJGfj">再用它们生成一条 <code>SIR</code> 轨迹，然后在 <code>I(t)</code> 和 <code>R(t)</code> 上加一点小噪声。</p><p data-pid="vl2-czlN">这一步的意思是：</p><p data-pid="ruxhr_ti"><b>先假装自己只有观测值，再看能不能把原始参数找回来。</b></p><p data-pid="V4k06D8C">这一节的 takeaway：<b>先做合成数据，是最省力也最稳的验算方式。</b></p><h3>3. 残差是什么</h3><p data-pid="I73K0Ol9">拟合的核心不是“猜一个参数”，而是“算两条曲线的差”。</p><p data-pid="H0e8_9aE">这条差就叫残差。</p><p data-pid="kLkpVMBk">如果观测值记成 <code>y_obs</code>，模型预测值记成 <code>y_pred</code>，那最朴素的残差就是：</p><p data-pid="06PBrHKG"><img eeimg="2" src="/assets/blog/images/f215da259628f03e12ae.svg" alt=" \text{residual} = y_{\text{pred}} - y_{\text{obs}} "></p><p data-pid="HwdMEUwZ">如果我们同时盯住 <code>I(t)</code> 和 <code>R(t)</code>，那残差就可以拼成一个向量：</p><p data-pid="QtISPz-A"><img eeimg="2" src="/assets/blog/images/d9b93eed99bfa109d6ff.svg" alt=" r(\beta,\gamma) = \begin{bmatrix} I_{\text{pred}} - I_{\text{obs}} \\ R_{\text{pred}} - R_{\text{obs}} \end{bmatrix} "></p><p data-pid="GkDCklxI">求解器要做的事，就是不断调 <code>beta</code> 和 <code>gamma</code>，让这个残差向量尽量短。</p><p data-pid="9mJErlDV">这一节的 takeaway：<b>参数拟合本质上就是“把预测和观测之间的差压到最小”。</b></p><h3>4. <code>least_squares</code> 怎么找参数</h3><p data-pid="Ac4jtPxM">SciPy 里最顺手的工具之一是 <code>least_squares</code>。</p><p data-pid="PPyC3f3Q">它的人话版本就是：</p><p data-pid="qu5oI6QG"><b>你给我一个参数猜测，我帮你反复缩小残差。</b></p><p data-pid="4BybfD72">如果只拟合一个显式函数，<code>curve_fit</code> 也很好用。<br>但只要模型本身先要跑一遍 <code>solve_ivp</code>，<code>least_squares</code> 往往更顺手，因为它更通用。</p><p data-pid="HMlH0-xz">这里我们用 <code>least_squares</code>，因为它正好能把“微分方程 + 拟合”串起来。</p><p data-pid="KNE7O3uJ">这一节的 takeaway：<b><code>curve_fit</code> 适合直接拟合曲线，<code>least_squares</code> 更适合包着一个微分方程模型一起拟合。</b></p><h3>5. <code>solve_ivp</code> 和 <code>least_squares</code> 怎么接起来</h3><p data-pid="T1u-JuML">这一步的逻辑其实很朴素：</p><ol>
<li data-pid="CjccPJJY">
<code>least_squares</code> 先给一组参数</li>
<li data-pid="84NEh-cG">
<code>solve_ivp</code> 用这组参数算出整条轨迹</li>
<li data-pid="7ggcRknc">把轨迹和数据比差距</li>
<li data-pid="Rr5Z57AR">
<code>least_squares</code> 再改参数</li>
<li data-pid="hXMTkCcX">重复直到残差足够小</li>
</ol><p data-pid="l7CTxEJC">代码可以写成这样：</p><div class="highlight"><pre><code class="language-text">import numpy as np
from scipy.integrate import solve_ivp
from scipy.optimize import least_squares


def sir_rhs(t, y, beta, gamma):
    # y = [S, I, R]，分别是三只桶里的比例
    S, I, R = y

    # infection 对应 S -&gt; I 的流量
    infection = beta * S * I

    # recovery 对应 I -&gt; R 的流量
    recovery = gamma * I

    # 三个桶的净变化速度
    dS_dt = -infection
    dI_dt = infection - recovery
    dR_dt = recovery
    return [dS_dt, dI_dt, dR_dt]


def simulate(beta, gamma, t_eval, y0):
    # 这一步就是“给定参数，正向解出曲线”
    sol = solve_ivp(
        lambda t, y: sir_rhs(t, y, beta, gamma),
        (t_eval[0], t_eval[-1]),
        y0,
        t_eval=t_eval,
        method="RK45",
        rtol=1e-8,
        atol=1e-11,
    )
    if not sol.success:
        raise RuntimeError(sol.message)
    return sol.y


def residual(params, t_eval, y0, i_obs, r_obs, sigma_i, sigma_r):
    # params = [beta, gamma]
    beta, gamma = params
    s_pred, i_pred, r_pred = simulate(beta, gamma, t_eval, y0)

    # 残差向量：观测值和预测值的差
    r_i = (i_pred - i_obs) / sigma_i
    r_r = (r_pred - r_obs) / sigma_r
    return np.concatenate([r_i, r_r])</code></pre></div><p data-pid="7j1np189">这里有两个很重要的小地方：</p><ul>
<li data-pid="CFoBjhvM">
<code>simulate()</code> 负责“前向算曲线”</li>
<li data-pid="4mrOPYMK">
<code>residual()</code> 负责“把差距交给优化器”</li>
</ul><p data-pid="1LHNuGMy">也就是说，<code>solve_ivp</code> 还是那个正向求解器，<code>least_squares</code> 负责反向找参数。</p><p data-pid="jQ_Jf5JX">这一节的 takeaway：<b>参数识别就是把“正向模拟器”包进“反向搜索器”里。</b></p><h3>6. 结果怎么看</h3><p data-pid="UJES30mO">拟合完成后，最值得看的不是“参数是不是精确到小数点后很多位”，而是三件事：</p><ol>
<li data-pid="TL6Lrh8A">拟合曲线有没有压住数据点</li>
<li data-pid="tY9plzfz">拟合出来的参数是不是还讲得通</li>
<li data-pid="UI_Oopmn">残差是不是还有明显结构</li>
</ol><p data-pid="UncrL5pX">如果曲线看上去贴得很紧，但参数已经离谱，那往往说明：</p><p data-pid="M8tTajEF"><b>你的模型写得太简单，或者数据本身不够支撑这些参数。</b></p><p data-pid="jz-yhyCt">如果残差不是随机散开的，而是有系统偏差，那说明：</p><p data-pid="82udjsB8"><b>模型缺了东西。</b></p><p data-pid="6Fs-Waj1">这一节的 takeaway：<b>拟合好不好，不只看图像贴不贴，还要看参数和残差有没有讲得通。</b></p><figure data-size="normal"><img src="/assets/blog/images/4474dbb2be0a8e8a49e7.png" data-caption="" data-size="normal" data-rawwidth="2816" data-rawheight="1144" class="origin_image zh-lightbox-thumb" width="2816" data-original="/assets/blog/images/4474dbb2be0a8e8a49e7.png" data-original-token="v2-0767bd06eb5a2a2c11f570e937aab79e"></figure><p class="ztext-empty-paragraph"><br></p><h3>7. 一个很现实的提醒</h3><p data-pid="mesRIFxB">只拟合一条曲线，常常不够。</p><p data-pid="ZHJ50M9f">这是因为不同参数有时会“互相顶替”：</p><ul>
<li data-pid="g90yQvwn">
<code>beta</code> 大一点</li>
<li data-pid="XH6e5dAW">
<code>gamma</code> 也大一点</li>
<li data-pid="uH4R_VKG">结果曲线还是差不多</li>
</ul><p data-pid="EeU15z5-">所以真实建模里，最好同时利用更多信息：</p><ul>
<li data-pid="Ce2zcCQP">多个观测量</li>
<li data-pid="F_dq18UP">不同时间段的数据</li>
<li data-pid="rYdhgtcz">边界条件或先验经验</li>
</ul><p data-pid="-b7Wkl6r">这不是在“增加麻烦”，而是在给参数更多约束。</p><p data-pid="BXlMaga0">这一节的 takeaway：<b>数据越少，参数越容易互相替代；数据越完整，拟合越稳。</b></p><h3>8. 小结</h3><p data-pid="v9wA04eg">这一篇压成一句话就是：</p><p data-pid="d7Pelosc"><b>微分方程不只是拿来往前算的，它也可以拿来反推参数；做法就是用 <code>solve_ivp</code> 生成预测，再用 <code>least_squares</code> 把预测和观测之间的残差压下去。</b></p><p data-pid="AhSJIXoi">如果只记五句话，就记这五句：</p><ul>
<li data-pid="gG8FTmOV">
<code>SIR</code> 是 <code>Susceptible-Infectious-Recovered</code>
</li>
<li data-pid="JUOMaq7h">
<code>beta</code> 和 <code>gamma</code> 是速率，不是概率</li>
<li data-pid="HcheGgK3">参数和状态变量不是一回事</li>
<li data-pid="sljpVO9T">
<code>solve_ivp</code> 负责正向模拟，<code>least_squares</code> 负责反向找参数</li>
<li data-pid="K67I8CHH">拟合不能只看曲线，还要看残差和参数是否合理</li>
</ul><p data-pid="7_NQAa9l">下一篇我们换到 <code>FiPy</code>，看污染物为什么会一边走一边散。</p><h3>参考</h3><ul>
